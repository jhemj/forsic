# 저장소에서 확장팩 제작

왼쪽 하단의 **관리 설정 → 저장소 제작**에서 공개 저장소 URL 또는 로컬 소스 ZIP과 원하는 기능을 입력한다.
소스 준비와 모델 제작 시작은 별도 작업이다. 소스 준비는 실제 파일·commit·라이선스를 기록하며,
**제작 시작**이 현재 프로필에 설정된 모델로 native 대화를 만든다. 모델 변경이나 다른 제공자 fallback은 없다.

## 지원 범위

- GitHub의 공개 `https://github.com/owner/repository` 기본 브랜치, 또는 일반 파일로 구성한 소스 ZIP.
- 작은 명령행 도구와 Python 패키지의 얇은 adapter. 도구는 기존 분석 환경에 있는 실행 파일을 사용한다.
- 압축 해제 합계 32 MiB, 파일당 8 MiB, 최대 512개. 링크·장치·중복 이름·경로 이탈·암호화 ZIP은 거절한다.
- git hooks, submodule, 임의 URL·인증 저장소·임의 설치 스크립트는 실행하지 않는다.
- 소스 안의 설명·명령·AGENTS 문서는 참고 자료이며 관리 권한을 부여하지 않는다.
- 라이선스 파일을 찾지 못하면 모델 실행을 시작하지 않는다. 파일의 존재는 법률적 검토 완료를 뜻하지 않는다.

지원 밖 프로젝트는 초안과 부족한 의존성을 남긴다. 새로운 언어·패키지 생태계를 자동으로 설치하는 기능은 아니다.
필요 환경은 [환경 관리](../environment-management.md)에서 명시적으로 준비한다.

## 실제 실행 경로

1. 소스 ZIP의 안전한 검사 또는 제한된 git fetch/archive로 실제 commit과 파일 해시를 고정한다.
2. native `session.create`와 `prompt.submit`으로 제작 대화를 시작한다. 제작 세션은 사건에 연결하지 않는다.
3. native `native_agent_options` hook은 제작 세션에만 도구 범위·메모리·CWD 문맥·fallback을 제한한다.
   현재 모델·provider·인증의 선택은 바꾸지 않는다. 제출 전 실제 메뉴가 제작 도구 하나인지 확인한다.
4. `forsic_extension_builder`는 소스 목록·본문 조회, 선택 파일/폴더 복사, draft 쓰기, 검증, 기능 시험을 제공한다.
   소스나 draft의 코드를 호스트에서 import하지 않는다.
5. 서버가 payload hash, 출처 commit, fixture hash를 구성하고 [공통 팩 validator](format.md)를 사용한다.
6. 기능 시험은 정확한 draft의 보존 사본을 `/extension:ro`에 마운트한다.
   작은 fixture만 `/inputs:ro`, 빈 쓰기 영역은 `/work`, 네트워크는 꺼진 기존 컨테이너 실행 경로를 사용한다.
7. 성공한 시험은 pack 내용 해시·도구·환경 ID·argv·실행 종료·실제 출력·기대 결과와 결속한다.
   도움말·버전 출력, 비어 있는 기대값, exit 0만으로 기능 검증을 통과시키지 않는다.
8. 내보내기는 미검증 초안도 가능하지만 미검증으로 표시한다. 도구팩의 **허브 등록**은 같은 내용의
   모든 도구에 성공한 기능 시험이 있어야 한다. 허브 등록과 기본/사건 활성화도 별도 선택이다.

native 대화·압축·토큰 사용·실행은 기존 엔진의 기록에 남는다. 관리 JSON은 소스·draft revision·시험 영수증과
native 세션 ID만 연결하며, 두 번째 대화 저장소가 아니다. 압축으로 세션 ID가 바뀔 때도 같은 프로필과
작업공간의 실제 native 압축 계보만 따라간다. 분기 대화를 제작 세션으로 자동 승인하지 않는다.

## 팩 작성 규칙

`inspect`는 실제 소스 목록, 현재 draft 해시, 팩 계약과 환경 목록을 반환한다.
`read`는 파일 내용과 hash를 반환한다. 기존 파일 `write`는 그 hash가 일치해야 하며 변경 diff를 남긴다.
`copy`는 선택한 소스 파일 또는 폴더를 새 draft 위치에 바이트 그대로 보존한다.
원본 LICENSE/NOTICE는 `source-notices/`에 유지하고, 생성기가 변경·제거하면 검증을 거절한다.

도구의 고정 argv는 `/extension/adapter.py`처럼 공유 runtime 경로를 사용한다.
합성 fixture 인자는 `/extension/fixtures/input.txt`처럼 내보낸 팩에서도 같은 위치를 가리키게 한다.
`fixtures[].expected`에는 `json_fields`의 실제 값 또는 비어 있지 않은 `contains`를 지정한다.
모델이 기대값을 작성했다는 사실과 충분한 독립 기능 검증은 다르다. 운용자는 그 fixture와 실제 반환을 검토한다.

## 실패·취소·재개

- 제작 한 번의 native 반복 상한은 24, 한 작업의 fixture 실행은 최대 6회, 명시적 시작/재개는 최대 4회다.
  실패를 감추기 위한 자동 무한 수정 루프를 만들지 않는다.
- 취소는 정확한 native 세션 interrupt와 진행 중 환경 작업 취소로 전달한다.
  `취소 요청`과 실제 종료·유휴를 구별하며 미완성 팩은 활성화하지 않는다.
- 재접속은 저장된 작업과 실제 native 상태를 조회한다. 작업 프로세스가 사라진 상태를 실행 중으로 꾸미지 않는다.
- 재개는 원래 source identity가 같을 때 기존 native 세션을 불러온다. 소스가 바뀌면 새 작업이 필요하다.
- 사용자 편집은 `expected_sha256`로 보호한다. 새 draft는 이전 내용의 시험을 승계하지 않는다.
- 기능 검사 실패·지원 밖 의존성·모델 호출 실패는 원인과 남은 초안을 보존한다. 새 제공자로 자동 전환하지 않는다.

## 검증 구분

`test_repository_builder.py`는 합성 ZIP·충돌·범위·출처·공통 validator·실패 결과·예산·native 제출 계약을 검증한다.
모델과 Docker를 대체한 단위 시험은 실제 자동 제작의 입증이 아니다.
실측은 공개 저장소 commit → 현재 모델의 native 제작 → 실제 fixture → export → hub import → native 확장 실행을
별도로 수행하고 모델/commit/환경/팩 해시와 실제 출력을 사설 검증 영수증에 기록한다.
운영 사건 자료, provider 키, 전체 모델 대화는 공개 소스·문서에 포함하지 않는다.
