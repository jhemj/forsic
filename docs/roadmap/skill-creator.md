# 선제적 스킬 크리에이터

> 상태: 제한된 절차 스킬 제안·검토·게시·명시적 활성화 구현. 기본 제공 스킬 교체는 검토 전용이며 미구현이다.

현재 구현과 API 계약은 [재사용 절차 스킬](../extensions/workflow-skills.md)에 있다.

주 에이전트는 실제로 관측한 성공/정정 절차에서 재사용할 이유, 적용 조건과 한계를 판단하고 현재 사건의 성공한
실행 영수증을 선택한다. 반복 횟수만으로 품질을 확정하거나 별도 학습 프로세스를 실행하지 않는다.
먼저 기존 스킬을 개선할 수 있는지 확인한다. 새 도구·adapter가 필요한 작업, 일회성 스크립트, 사건 사실·운영기억은
절차 스킬 게시와 별개다. 제안으로 저장소 제작기나 환경 설치를 시작하지 않는다.

비공개 초안은 기존 tenant/profile 관리 저장소에 원래 사건과 정확한 영수증 hash, 대상 revision과 함께 보존된다.
주 에이전트는 제안만 할 수 있다. 사용자는 diff와 `draft_sha256`를 검토한 뒤 새 불변 확장 버전의 게시를 승인하고,
그 후 현재 사건 또는 프로필 기본값의 활성화를 별도로 선택한다. 활성화는 기존 확장 허브/환경 선택/native runtime
갱신 경로를 사용하며 실제 적용을 확인하지 못하면 pending을 반환한다. 게시·구조 검증·기능 확인·활성화를 구별한다.

기존 확장의 단일 `SKILL.md` 절차 개선과 새 절차 스킬은 이 흐름을 끝까지 지원한다. 기본 제공 스킬은 정확한 현재
내용 hash와 diff를 보존하는 검토만 지원한다. 기본 제공 스킬을 덮어쓰거나 같은 이름의 중복 확장으로 우회하지 않는다.
기본 제공 절차의 안전한 overlay 교체와 참조/도구를 포함한 복합 팩 개선은 후속 과제다.

사건명·계정·주소·증거 경로·원문 발췌·비밀값은 초안에서 일반화한다. 알려진 값 비교와 native 자격정보 검사를
수행하지만 완전한 개인정보 가림을 보장하지 않는다. 일반 경로와 placeholder 기반 명령 예시는 허용하며,
실행 스크립트·도구·설치 의존성·설치 지시는 이 경로에서 게시하지 않는다. 원문은 사건 저장소에 남긴다.

거절/철회 상태와 같은 fingerprint의 중복 억제, draft 수정 뒤 옛 승인 거부, 대상 변경 충돌, 원장 출처 변조,
저장 실패와 동일 내용 재시도, 관리 HTTP와 사건별 pending 활성화는 합성 오프라인 시험으로 검증한다.
테넌트 관리 권한이나 운영기억 저장 승인은 스킬 게시·공유 승인으로 재사용하지 않는다. 다른 테넌트의 기록을 모으지 않는다.

후속 검증은 실제 모델이 의미 있는 절차를 적절히 일반화하는지, 중복 스킬을 피하는지, 다음 독립 합성 사건에서 유용한지와
입출력·캐시 비용을 따로 측정해야 한다. 현재 회귀시험은 이 의미 평가나 실제 조사 정확도 향상을 입증하지 않는다.
공용 배포·다른 테넌트 공유·정기 후보 순회·전역 background_review 활성화는 구현/승인 범위에 포함되지 않는다.
