# Ren의 선택적 별도 모델 연결

설정은 최대 두 연결을 사용한다. 포식이의 주 모델은 기존 연결을 유지한다. 설정 → 모델 → 렌 검토 모델의 `추가 모델 사용`을 켜면 이후 새 독립 검토 요청은 설정한 두 번째 서버 주소와 모델만 사용한다. 끄면 기존 주 모델 연결 방식으로 검토하며, 별도 서버·모델·키 참조는 편집할 수 있도록 보존한다. 실행 중인 검토는 시작할 때 고정한 연결과 키를 끝까지 사용한다.

Ren은 기존 native auxiliary 요청으로 제한된 별도 system/user 문맥을 검토한다. 주 대화 기록을 복제하지 않으며 별도 에이전트 루프나 스케줄러를 만들지 않는다. 기존 요청 횟수·입력/응답 크기·시간 한도, 취소, 출처 좌표와 불변 요청/응답 기록 계약을 유지한다. 검토 호출 자체의 동의와 native 목표 경계는 기존 `independent_review` 설정을 따른다. 두 번째 연결 활성화만으로 검토를 실행하지 않는다.

두 번째 연결이 활성화되어 있으면 설정 오류, 키 누락, 서버 오류에도 주 모델로 자동 전환하지 않는다. 오류와 전달 미확정 상태는 기존 검토 상태에 남는다. `auto` 대신 사용할 정확한 모델 이름을 지정해야 한다. 설정 조회·저장은 모델이나 서버를 호출하지 않는다.

API 조회의 `ren_llm`은 `enabled`, `base_url`, `model`, `key_configured`만 반환한다. 저장 필드는 `ren_llm_enabled`, `ren_llm_base_url`, `ren_llm_model`, `ren_llm_api_key`, `clear_ren_llm_key`다. 생략한 필드는 기존 값을 보존한다. 활성화하려면 유효한 HTTP(S) 주소와 모델 이름이 모두 필요하다. 비활성 상태에서는 주소·모델을 비워 둘 수 있다.

키는 선택 사항이며 주 모델 키와 분리된 native 프로필 `.env` 슬롯에 저장한다. 키 입력을 생략하면 기존 키를 보존하며, 빈 문자열 또는 공백만 입력하면 키 없이 사용한다. 새 값은 앞뒤 공백을 제거해 교체하고, `clear_ren_llm_key: true`도 키 없이 사용으로 처리한다. 키가 설정된 서버 주소를 변경할 때는 새 키 또는 기존 키 삭제를 함께 선택해야 한다. URL에 인증정보·쿼리·fragment를 포함할 수 없다. 키 없는 서버에는 명시적인 `no-key-required`만 전달하며 주 모델·환경의 다른 제공자 키를 빌리지 않는다. 키 참조가 있으나 현재 프로필에서 키를 읽을 수 없으면 검토를 전송하지 않는다. 키 값은 설정 응답, 설정 YAML, 검토 기록에 넣지 않는다.

새 테넌트는 Ren 주소·모델·활성 상태 및 native `key_env` 참조를 상속한다. 원래 프로필의 자격정보·대화·검토 기록은 복제하지 않는다. 따라서 키가 필요한 상속 연결은 새 테넌트의 설정에서 별도 키를 저장해야 사용할 수 있다.


## 주 모델 키와 저장 경계

연결 설정 API의 주 모델 필드는 `llm_api_key`와 `clear_llm_key`다. 초기 설정 API도 같은 계약을 사용한다. `llm_api_key`를 생략하면 실행 중이거나 이미 저장 대기 중인 키 선택을 보존한다. 빈 문자열·공백만 입력하거나 `clear_llm_key: true`를 지정하면 키 없이 사용한다. 값이 있는 키와 삭제 플래그를 함께 지정하면 거부한다. 기존 키나 대기 중인 교체 키가 있는 서버의 주소를 바꿀 때는 새 키 또는 키 없이 사용을 명시해야 한다. 키의 `null`, 객체, 배열은 허용하지 않는다.

연결 조회의 `llm.key_configured`와 초기 설정 조회의 `llm_key_configured`는 저장 대기 중인 선택을 반영한다. `llm_current`는 현재 실행 연결을 나타내고, `llm_pending`은 다음 명시적 대시보드 실행에서 적용할 주 모델 변경이 있는지 알려준다. 조회와 저장은 모델 요청을 보내지 않는다.

주 모델의 주소·모델·키 참조는 기존 launcher의 적용 단계에서 같은 native 설정 저장으로 전환한다. 저장만으로 실행 중인 주 모델의 키를 교체하지 않는다. 두 설정 화면은 기존 `setup_pending` 키 선택과 `llm_pending` 연결을 공유하며 별도 적용기를 추가하지 않는다. 교체 키는 native `.env`의 새 슬롯에 먼저 저장하고 설정에는 그 참조만 넣는다. 설정 저장 실패 시 기존 활성 키나 기존 대기 키를 덮어쓰지 않는다. Ren의 교체 키도 주소에 결속된 새 슬롯을 사용하며 설정 저장 성공 후 이전 참조를 정리한다. 다른 연결에서 참조 중인 슬롯과 다른 제공자의 키는 삭제하지 않는다.

주 모델의 키 없이 사용은 native `no-key-required`로 명시하며 환경의 다른 제공자 키나 예전 custom credential pool을 선택하지 않는다. 별도 Ren 연결을 끄면 독립 검토는 현재 주 모델의 주소·모델과 그 연결에 설정된 키만 사용한다. 주 모델 키 참조를 현재 프로필에서 읽을 수 없으면 다른 키로 우회하지 않는다. Ren을 켰을 때의 연결 분리와 실패 시 자동 전환 금지는 그대로 유지한다.

초기 설정의 모델 목록 확인 API도 키 입력 생략과 빈 입력을 구별한다. 생략하면 정확히 일치하는 선택 서버의 대기 키 또는 현재 연결 키를 사용하고, 빈 문자열·공백만 입력하면 인증 헤더 없이 확인한다. 편집한 다른 주소에는 현재 연결의 키를 보내지 않는다. 키와 잘못된 비밀 입력값은 설정 응답·검증 오류·설정 YAML에 반환하지 않는다.
