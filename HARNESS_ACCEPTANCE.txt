Forsic 하네스 구현·수용 기준 — P0/P1/P2/P3/P4 및 P5 비교 준비

설계 기준
Pro의 f8ba261 검토에 따라 native 실행 엔진과 포렌식 도메인의 책임을 분리한다.
Hermes는 현재의 단일 운영 엔진이다. 별도 실행 루프·압축기·모델 판정기를 만들지 않는다.
다른 엔진을 영구 배제하지 않지만, 같은 조건의 기준선과 실제 한계 없이 교체하지 않는다.
P6/P7이라는 번호를 채우기 위한 기능은 정의하지 않는다.

현재 구현
P1: 직접 읽기/검색 → 명시적 C2/C1 선택 → 질문의 현재 판단 → 추가 조사/보고.
    선택적 미션은 필요한 사전 판별 검사다. 판단 저장의 필수 관문이 아니다.
    기존 노트 단일 writer와 CAS/operation_id를 사용하며, 선언하지 않은 의무를 합성하지 않는다.
    유력 해석·가정·반론과 불확실한 범위 종결을 보존한다. 정확 인용은 의미 승인이 아니다.
P2: 실제 admission/start/return/commit/delivery를 구분하고 native 취소를 연결한다.
    종료 미확인·결과 유실은 기존 실행 조회로 복원하며 자동 중복 실행으로 덮지 않는다.
P3: 현재 판단·반론·한계·범위·실패와 정확한 source/execution 조회를 작은 문맥에 보존한다.
    검증된 native lineage만 복원하며 선택 보고의 freshness와 미포함 질문을 명시한다.
    웹 시작 실패는 명시적으로 반환하고, 짧은 연결의 무한 재시도를 제한한다.
    배포는 실제 native TUI/Web 빌드 영수증을 확인한다.
    알려진 로컬 제공자 유형도 다시 HTTP로 검증하되, 무관한 유형의 탐색을 먼저 하지 않는다.
P4: 현재 시간축 기능을 모델의 실제 질문 저장 경로에 연결한다.
    time_source와 정확 원문 좌표/메타데이터 필드를 기존 writer에서 검증·정규화한다.
    새 입력의 임의 계산 시각은 허용하지 않는다. 연도/시간대 미상은 미상으로 보존한다.
    정정 시 현재 시간축만 대체하고 과거 노트·원문·보고서는 보존한다.
    시간축·개인정보 범위·외부 평판·후속 질문 스킬을 실제 도구와 일치시킨다.
    구형 forsic_note 저장은 내부 호환 경로이며 native 모델 메뉴는 list/get만 제공한다.
    반복된 검색 입력 실패에 대응해 forsic_image_search는 path/file_path/text를 모두 필수로 받는다.
    기존 image reader의 search 실행으로 결속하며 대상·질의·볼륨을 추측하지 않는다.
    새 검색·이어읽기·선택적 미션·압축 결과 조회는 같은 canonical 원장과 참조를 사용한다.
    구형 검색 기록은 보존하고 native 일반 이미지 메뉴에서는 중복 search 선택지를 숨긴다.

지원 범위와 전문 기능 선택
- 일반 파일: 정확한 텍스트/바이트 읽기, literal 검색과 이어읽기, 전체 해시.
- E01: 기존 Dissect reader의 할당 파일/볼륨 목록·stat·읽기·검색·해시.
- TAR/TAR.GZ: 보존된 목록 참조와 실제 제시된 멤버 번호로 명시 선택한다.
  여러 볼륨·중복 이름·링크·stale metadata를 검사하고 metadata_checked의 한계를 보존한다.
- 시간축: 보존된 log literal/UTF-8 좌표, stat, 정확 listing entry로 출처를 결속한다.
  시간대가 있는 ISO 시각만 절대시각으로 변환한다. 파일 시각을 실행/성공으로 해석하지 않는다.
- 바이너리 미리보기는 레코드 디코딩이 아니다. 현재 triage는 Windows EVTX의 Hayabusa 후보와
  명시적 ABI의 Linux 로그인 레코드 파싱을 제공하며, parser/범위/부분 실패와 원문 재검토를 구분한다.
  journald/SQLite/메모리·삭제 영역 복구·카빙을 모두 지원한다고 주장하지 않는다.
- 격리 터미널은 기존 제한 안에서 파생 /work 자료를 처리한다. 일반 CSV/JSONL의 제한된 SQL
  질의는 출처·행/바이트 좌표·입력 해시·거절 행·생략을 보존한다. 임의 호스트 실행이 아니다.
  구체적 미지원 자료는 형식·필드·범위·오류를 확인한 뒤 기존 도구와 어댑터를 선택한다.
- 이미지 파서는 RO 증거/reader mount, 네트워크 없음, 비특권 사용자, capability 제거,
  no-new-privileges, 메모리/PID 한도를 유지한다. 실제 격리 공격 시험 통과와는 별개다.

오류와 자율성
잘못된 인자·초안·중간 판단을 한 번 만났다는 이유로 전체 초기화하지 않는다.
같은 질문에서 실제 정정할 기회를 관측하고, 정정된 답이 후속 보고/압축에 유지되는지 확인한다.
원본/권한/사건 경계, 실제 근거 조작, native halt와 실측 교착은 별도로 즉시 다룬다.
핵심 분석 오류는 실질적 정정 기회 뒤에도 남거나 최종 사용에 반영됐는지로 판단한다.
자율성은 오류가 없다는 보장이 아니다. 복구·근거 추적·중요 조사·유용한 답으로 평가한다.

검증과 P5
HARNESS_ACCEPTANCE.json은 Pro의 24개 시나리오에 현재 검사를 연결한 준비 자료다.
관련 계약 검사(C), 실제 격리 도구(T), 고정 모델 행동(B)을 분리하며 24개 전체 통과표가 아니다.
S24의 감독 개입은 운영 전달 영수증으로 평가한다. 검사를 채우기 위한 개입/추가 호출은 없다.
test_specialist_contracts는 등록 핸들러→writer→원장→HTML/Word까지 합성 원문으로 검증한다.
test_evidence의 격리/timeout 시험은 실제 wrapper에 Popen/cleanup mock을 붙인다.
옛 native note-write 검사와 이전 대기시간 가정은 현재 계약에 맞춘다.
조건과 관측 위치는 JSON의 behavior_protocol과 각 시나리오에 둔다.
모델/양자화/서빙·sampling·자료·권한·도구·문맥·예산을 고정하고 한 축만 바꾼다.
입력 전체/캐시/신규, 출력, 압축, 실패 비용을 분리한다. 바이트 감소를 토큰/속도로 대체하지 않는다.
새 엔진·새 모델·독립 사건 실험이 기존 운영 제한을 넘으면 별도 승인이 필요하다.
동일 사건 복구 E2E는 독립 holdout이 아니며, 오프라인 통과는 자율 조사 성공이 아니다.
조건부 엔진 비교는 준비까지 마치고 실행하지 않았으면 not_run으로 유지한다.

배포·호환·롤백
새 DB·원장 변환·과거 증거 재작성은 없다. 새 시간축도 기존 노트 형식으로 저장한다.
구형 노트/보고·C1/C2·미션 dependency는 재생 가능하며 모델 입력만 지원 기능에 맞춘다.
원문·원장·출처·보고·진단을 보존한다. 승인된 대화 초기화는 실제 개선 배포 뒤 유휴에서 수행한다.
빈 parent/메시지0/pin과 한 번의 제출을 확인한다. 기존 P1 v2 writer rollback 계약을 따른다.
본 시간축 변경만 롤백해도 저장된 시간축은 기존 reader로 읽힌다.
배포 전후 파일·빌드 해시, 유휴, 설정, 실제 진행, 실패 시 rollback은 운영 영수증으로 확인한다.
단계별 설계·코드·오프라인·배포·실제 행동 검증을 구분한다.

CP05 대표 평가 준비
세 독립 CC0 합성자료는 tests/acceptance/manifest.json의 해시·크기·출처·읽기/파싱 한도로 고정한다.
모델에게는 inputs/<dataset>/만 제공하고 truth/와 README·manifest는 평가자에게만 둔다.
실제 판별 단서, 정상 설명, 부분 범위와 손상 레코드를 각각 포함한다.
test_acceptance_cases는 기존 read→질문 writer→잠정 답→명시적 합성 검토 영수증→정정·검토 응답 저장
→현재 투영→HTML/Word를 검증한다. 합성 검토는 모델 호출 없이 생성한 계약 fixture다.
별도 평가기·루프·keyword 의미 scorer는 없다. 정확 인용과 저장 일치만 자동 검사하고 의미는 독립 정답과
사람의 rubric으로 대조한다. 실제 도구 T 및 모델 행동 B는 not_run이며 자율 성공으로 집계하지 않는다.
