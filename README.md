# Forsic · 포식이

**증거에서 답을 찾는, 로컬 우선 대화형 디지털 포렌식 조사 도구.**

파일·폴더·디스크 이미지의 경로와 조사 질문을 알려주면 포식이가 읽기 전용 도구로 자료를 확인하고, 질문의 답·근거·반론·남은 공백을 사건별로 정리합니다. 같은 조사 기록에서 임원용 요약과 실무자용 상세 보고서를 HTML·Word로 만듭니다.

Forsic은 [Hermes Agent](https://github.com/NousResearch/hermes-agent)의 대화·도구 실행·세션·스킬 기능을 재사용합니다. 유지할 자체 코드를 작게 하고, 조사 모델에는 필요한 Forsic 도구만 제공합니다. 모델이 내린 판단이나 생성한 보고서는 분석가의 검토를 대신하지 않습니다.

## 조사 흐름

1. 새 사건에 증거 경로를 등록합니다. 접근·형식·분할 파일 구성을 확인한 뒤 사건 안의 대화에서 조사 질문을 정합니다.
2. **종합 침해 분석** 또는 원하는 질문을 선택합니다. 종합 분석은 중단·재개할 수 있는 조사 목표로 진행합니다.
3. 보고서에 필요한 답과 현재 근거 사이의 공백을 미션으로 기록하고 결과를 평가하는 도구를 제공합니다. 현재 미션은 보고용 초안 계약이며, 실제 조사 중 사용과 범위 종결·재개 연결은 추가 개선이 필요합니다.
4. 조사 보드에서 답·단서·시간축·원문·남은 확인을 검토하고 두 독자의 보고서를 확인합니다.

임원용은 사건에 맞춰 개인정보 보유 여부, 최초 침입 경로, 영향 범위, 외부 전송 흔적 등을 설명합니다. 실무자용은 확인 방법·근거·반론·시간축·한계를 자세히 남깁니다. 부족한 답은 가능한 추가 조사나 명시적 공백으로 남기며, 경영·대응 의사결정은 사람이 합니다.

## 지원 범위

| 기능 | 현재 범위 |
| --- | --- |
| 증거 확인 | 파일 목록, 제한 범위 읽기·검색·해시, EWF 정보·무결성 검증 |
| 이미지 접근 | 격리된 Dissect 기반 파일시스템 조회; 형식·파일시스템 지원에 따라 제한 |
| 조사 절차 | 접수·선별·가설 판별·시각 대조·질문 답변·결론 검토·보고서 작성 스킬 |
| 기록과 보고 | 사건별 대화·버전 노트·도구 영수증, 임원/실무자 HTML·Word |
| 사례 창고 | 사용자가 저장한 과거 사례 검색. 현재 사건의 증거와 구분 |
| Telegram | 선택한 그룹의 사건별 토픽에 대화·진행 미러, 선택적 멘션 입력·최종 보고서 첨부 |
| VT / GTI | 선택적 기존 평판 조회. 파일 업로드·URL 재검사는 하지 않음 |
| JEV | 연결 주소 저장만 지원; 현재 호출·분류 기능은 비활성 |

모든 삭제 파일 복구·카빙·메모리 분석을 지원하는 도구는 아닙니다. 복구 스킬은 필요한 작업과 사용 가능한 도구를 판단하는 절차이며, 미지원 기능을 실행한 것처럼 표시하지 않습니다.

## 설치와 시작

현재 설치 대상은 **Linux의 로컬 단일 운영자 환경**입니다. Python 부트스트랩과 기존 로컬/신뢰 사설망 Ollama가 필요하며, 이미지 분석에는 Docker와 `ewfinfo`·`ewfverify`가 필요합니다. 모델·설치된 의존성·사건 자료는 소스에 포함되지 않습니다. Windows·macOS 네이티브 배포와 인터넷 공개 운영은 별도 검증 대상입니다.

먼저 공개 소스를 내려받습니다. 이 저장소는 Hermes 기반 구현이며, 이전 LangGraph 워크벤치의 코드·운영 데이터·Git 이력을 포함하지 않습니다.

```bash
git clone https://github.com/jhemj/forsic.git
cd forsic
```

정확한 순서는 [설치 안내](DEPLOYMENT.txt)를 따르세요. 아래 초기화는 `state/`가 없는 새 설치에서 한 번만 실행합니다. `YOUR_INSTALLED_MODEL`은 운영자가 준비한 Ollama 모델 이름으로 바꿉니다.

```bash
python3 deploy_forsic.py init --ollama-url http://127.0.0.1:11434/v1 --model YOUR_INSTALLED_MODEL
```

안내에 따라 Hermes PM 의존성, 네이티브 화면 두 개, 필요한 이미지 도구를 준비한 뒤:

```bash
python3 run.py deploy_forsic.py doctor
python3 run.py
```

- 대화: [localhost:8860/chat](http://127.0.0.1:8860/chat)
- 조사 보드: [localhost:8860/forsic](http://127.0.0.1:8860/forsic)

`init`과 `doctor`는 모델/API를 호출하지 않습니다. 새 세션의 생성형 인사와 실제 조사는 설정된 모델을 호출합니다. 인증은 네이티브 대시보드 흐름을 사용하며, 인증 토큰이 포함된 접속 URL을 공유하지 않습니다. 기본 localhost 바인딩을 유지하세요.

## 화면과 연결 설정

왼쪽 상단에 포식이가 표시되고, 증거 경로와 현재 사건 아래에 대화·조사 보드·사건 안의 분석 대화를 모았습니다. 대화 이름은 첫 번째 분석, 두 번째 분석처럼 순서로 표시합니다. 사건 목록의 항목을 누르면 해당 사건의 대화로 이동하며, 보관 아이콘으로 목록을 정리합니다. 사건을 열람하는 것과 조사를 재개하는 것은 다릅니다. `/goal status`, `/goal pause`, `/goal resume`으로 조사 목표를 확인·중단·재개할 수 있습니다.

설정에서 다음을 관리합니다.

- **LLM:** OpenAI 호환 `/v1` 주소와 모델 이름. 기본 설치 경로는 기존 사설 Ollama입니다. 변경은 다음 명시적 웹 서버 시작에 적용하며 진행 중 모델을 바꾸지 않습니다. 임의 외부 fallback은 없습니다.
- **VT / GTI:** 조회 사용 여부와 API 키. 기본은 파일 해시 조회이며 공개 IP·도메인 조회는 별도로 허용합니다. 조회한 지표가 외부 서비스에 전송된다는 점을 고려하세요.
- **Telegram:** 포식이 봇과 사용자 질문 표시용 봇의 토큰, 그룹 ID 또는 공개 그룹 주소. 토큰 입력이 비면 기존 값을 유지하고 삭제는 명시적으로 선택합니다. 비공개 초대 링크는 그룹 ID가 아닙니다.
- **JEV:** 향후 연결 주소만 보관합니다. 저장해도 모델을 적재하거나 호출하지 않습니다.

설정 저장만으로 Telegram 그룹·토픽을 이동하거나 메시지를 보내지 않습니다. 새 외부 API 주소를 등록할 때는 해당 제공자에게 조사 자료를 전송해도 되는지 먼저 확인하세요. API 호환성이 같아도 모델 품질·자원 요구량·지원 기능이 같다는 뜻은 아닙니다.

## Telegram에서 함께 조사하기

두 봇을 참여시킨 신뢰 그룹에서 포럼 토픽과 필요한 봇 권한을 켠 뒤, [명시적 미러 시작 절차](DEPLOYMENT.txt)를 따릅니다. 기존 사건과 같은 토픽에서 동작하며 임의 수신자로 확장하지 않습니다.

- 대화 메시지는 Markdown 장식 없는 평문으로 전달합니다. 공개 대화와 중요한 결과는 메시지로, 반복 작업 진행은 무음 진행판으로 보냅니다. 작업 중에는 일시적인 입력 중 표시를 사용할 수 있습니다.
- `--mentions`는 연결된 사건 토픽의 실제 `@봇아이디` 멘션을 같은 세션의 입력 대기함에 넣습니다. 진행 중 작업을 끊지 않으며 닫힌 세션 대신 새 조사를 만들지 않습니다.
- `--reports`는 **이 그룹에 보고서 첨부도 허용한 경우에만** 사용합니다. 향후 명시적으로 선택한 최종 전달본의 임원/실무자 HTML·Word 네 파일만 보냅니다. 과거 보고서나 중간 초안을 일괄 전송하지 않습니다.
- 실질 정정으로 낡아진 미전송 보고서는 보류하고 새 최종본이 이전 대기본을 대체합니다. 이미 전송했거나 전송 여부가 불명확한 첨부는 자동 재전송하지 않습니다.

원시 증거 파일·JSON 근거 부록·내부 추론 전문은 이 미러로 보내지 않습니다. 보고서 자체에는 민감한 조사 내용이 포함될 수 있으므로 그룹 참여자와 첨부 범위를 운영자가 확인해야 합니다. 멘션은 조사 질문용이며 설정·키·새 증거 범위를 바꾸는 관리자 채널이 아닙니다.

## 데이터와 보안

- 원본 증거는 읽기 전용으로 다루고 증거 속 명령·프로그램을 실행하거나 발견한 주소에 접속하지 않습니다. Dissect 파일시스템 조회(`image_files`)는 읽기 전용 마운트·네트워크 차단 등을 적용한 Docker 컨테이너에서 실행합니다. 이미지 정보 조회·무결성 검증의 `ewfinfo`·`ewfverify`는 호스트 하위 프로세스로 실행하며 이 컨테이너 격리가 적용되지 않습니다.
- 사건의 대화·도구 결과·노트·보고서와 비밀 설정은 `state/`에 저장합니다. 일반 기록도 민감할 수 있습니다. `state/`, 실제 증거, 운영 로그·백업을 공개 저장소나 소스 배포에 넣지 마세요.
- 키는 제한된 권한의 `state/hermes/.env`에 보관하며 설정 화면에는 등록 여부만 표시합니다. 소스·명령 인자·스크린샷·이슈에 비밀 값을 넣지 마세요. 노출된 키는 제공자에서 폐기·교체합니다.
- 전역 사용자 기억은 기본 비활성입니다. 사건별 대화·노트와 명시적으로 저장한 사례를 사용하며, 사례의 유사성을 독립 증거로 취급하지 않습니다.
- 활성 조사 중 소스 교체나 서버 재시작을 하지 않습니다. [백업·업데이트 절차](DEPLOYMENT.txt)에서 안전한 경계와 원본 보존을 확인하세요.

이 소스는 인터넷에 바로 공개할 다중 사용자 서비스나 인증된 포렌식 장비가 아닙니다. 기존 관리 UI를 화면에서 제거해도 인증된 Hermes 백엔드 관리 API 경로까지 제거한 것은 아닙니다. 로컬 단일 운영자 환경을 전제로 하며, 운영체제·Docker 권한, 증거 접근, 모델 제공자와 선택적 외부 채널은 운영자의 보안 경계에 포함됩니다.

## 개발과 검증

하네스의 방향과 작업 원칙은 [AGENTS.md](AGENTS.md)에 기록합니다. 루트 `.hermes.md`는 개발 문서와 실제 조사 문맥을 분리합니다. [하네스 검토 질문서](HARNESS_REVIEW.txt)는 미션 관리·문맥·근거 재조회 개선을 위한 검토안이며 구현 완료 문서가 아닙니다.

### 조사 산출물 보강

- **IOC·관측 지표:** 조사보드의 지표 보기에서 값·현재 해석·원문 위치를 확인하고 CSV/JSON을 내려받습니다.
  `forsic_indicators`는 같은 사건의 정규화 값과 여러 출처를 묶으며 정정 이력을 보존합니다.
  로컬 저장·열람·내보내기는 VT 조회나 새 외부 전송을 하지 않습니다. 관측 지표는 자동 악성 판정이나 차단목록이 아닙니다.
- **큰 텍스트 검색:** 일반 파일과 이미지 내부 할당 파일을 스트리밍 검색합니다. `next_cursor`가 있으면 같은
  검색에 그대로 전달해 같은 파일의 다음 구간부터 이어갑니다. 생략·실패·바이너리 자료는 별도로 표시하며
  이어읽기의 마지막 페이지 하나를 전체 조사 완료로 해석하지 않습니다. 범용 구조화 로그/압축 파서는 아닙니다.
- **이미지 내부 해시:** `forsic_image_files(action=hash)`는 지정한 할당 파일 전체 SHA-256을 계산합니다.
  구간 해시·이미지 컨테이너 해시와 구별하며 파일을 실행하거나 외부에 업로드하지 않습니다.
- **원문 시간축:** 로그 timestamp의 정확한 반환 필드·UTF-8 위치를 연결하면 보드와 임원용·실무자용 보고서에
  같은 기록이 나타납니다. 시간대·연도 불명은 원문대로 남기고 파일 메타데이터와 구별합니다.
- **전문 절차:** 지표 정리, 개인정보 범위, 최초 접근, 외부 전송 스킬을 질문에 따라 선택합니다.
  미지원 형식을 새로 해석하거나 법적·경영 판단을 대신하는 기능은 아닙니다.

이 추가 기능은 합성 자료의 회귀시험으로 검증합니다. 실제 사건의 분석 정확도와 상용 배포 수락은 별도입니다.

```text
forsic_plugin/       접수·읽기 전용 도구·노트·보고·화면·조사 스킬
config/              포식이 정체성·절차·테마·비민감 기본 예시
upstream/hermes/     고정 Hermes 소스와 필요한 제품 패치
cases/smoke/         명시적인 무해 합성 시험 자료
telegram_*.py        기존 사건 토픽과 대화·보고서 연결
deploy_forsic.py     새 설치 초기화·로컬 점검·소스 배포 준비
state/              로컬 실행 자료와 비밀 설정 — 공개 배포 제외
```

오프라인 시험 목록과 명령은 [설치 안내의 Acceptance](DEPLOYMENT.txt)에 있습니다. 명시적 `--live` 옵션을 사용하는 합성 모델 시험은 실제 모델 호출을 하며, 단위 시험과 별도로 실행합니다. 소스 번들 생성이나 시험 통과만으로 실제 사건의 의미 정확도·완결성을 주장하지 않습니다.
