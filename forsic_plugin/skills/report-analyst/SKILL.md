# 분석가용 보고서
새 보고는 forsic-report-driven을 읽고 forsic_reporting(action=render)로 같은 답·F-ID·한계의
임원/실무자 HTML·Word를 함께 만든다. 과거 forsic_report 생성 경로와 섞지 않는다.
현재 질문의 가장 유력한 답·질적 신뢰도와 이유, 실제 도구 결과, 범위와 공백을 모은다.
직접 관측과 추정 연결을 구분한다. 불완전한 증거도 경쟁 설명과 비교해 분석 판단을 제시한다. 두 독자는 같은 snapshot을 사용한다.
본문에는 질문 답변, 조사 범위·방법, 발견별 관측과 해석, 정상 설명, 시간축과 제한 사항을
쓴다. 모든 호출을 본문에 쌓지 않는다. 원문과 작업 명세는 출력기의 JSON 근거 부록에 남는다.
요약의 출처 파일명과 각 결론을 실제 도구 결과에 대조한다. 가능한 정상 설명은 침해
부재 증명이 아니다. 미확인 원인을 확정하거나 이름만 다른 같은 설명을 반론으로 늘리지 않는다.
핵심 발견마다 실제로 본 입력과 반환 내용을 구분한다. 명령을 봤는지, 결과 출력을 봤는지,
실행 효과까지 확인했는지 설명하고 해당 원문을 인용한다. 부재를 말할 때는 검색어·원문 범위·
관측 시점을 함께 쓴다. not_found를 삭제 입증으로, 예약 설정을 실행 성공으로 바꾸지 않는다.
행위자·세션 연결에는 주소나 가까운 시각 외의 연결 근거를 제시하고 시각 출처와 불확실성을 남긴다.

최종 초안은 review-conclusions 절차로 검토한다. 현재 답·미평가 결과·핵심 공백을 다시 읽고,
답을 바꿀 수 있는 공백은 실행 가능한 다음 판별 미션으로 연결한다. 내부 검토 시간초과나 참조
오류를 외부 자료 부재로 쓰지 않는다. 검토 미완료·무결성 미확인은 그 상태대로 보고한다.
실패/예산 소진 시 저장된 현재 답으로 부분 보고서를 만들고 답하지 못한 질문을 남긴다.
정정은 새 보고 버전으로 저장하고 이전 파일과 원문은 보존한다. 파일 생성과 모든 조사 질문의
해결은 별개다. 같은 파일을 이유 없이 다시 만들지 않는다.
전달용 최종본은 forsic-report-driven의 finalize 단계로 임원용과 함께 기존 사건 Telegram
토픽에 첨부한다. 원시 증거·근거 JSON 부록은 전송 범위가 아니며 전송 영수증 없이 완료라고 말하지 않는다.
