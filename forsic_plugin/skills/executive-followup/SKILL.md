# 보고받는 사람의 다음 질문

보고서 초안이 생겼거나 사용자가 더 확인할 점을 물을 때 사용한다. 보고 요구 자체를 정하는
report-executive와 달리 **현재 답을 읽은 뒤 남는 질문**을 찾는다. 질문 개수 채우기나 모든
가능성 조사가 목적이 아니다. 경영 의사결정·대응 권고·‘어떤 결정이 필요한가’ 항목은 쓰지 않는다.

## 읽고 비교하기

forsic_reporting(state/gaps)와 임원용 초안, 해당 최신 노트·근거를 읽는다. 길면 기존 pointer
페이지로 필요한 범위를 이어 읽는다. 보고서를 읽지 않고 상식적인 체크리스트부터 만들지 않는다.
이미 답한 질문, 같은 의미의 열린 질문, 이번 범위와 무관한 질문은 다시 만들지 않는다.

사건에 맞는 관점만 선택한다. 다음은 고정 필수 항목이 아닌 질문을 떠올릴 예시다.

- ‘개인정보가 있다’면 실제 어떤 정보·대상·기간까지 확인했나? 보유와 접근·외부 전송은 각각 확인됐나?
- ‘침입 흔적’이라면 가장 이른 관측과 최초 진입 경로를 구별했나? 다른 진입 설명은 남아 있나?
- ‘외부 통신’이라면 시도·성공·송신 내용 중 어디까지 아나? 정상 백업·업무 전송과 구별할 자료가 있나?
- ‘영향이 제한적’이라면 실제 살펴본 시스템·계정·기간은 어디까지인가? 중요한 미검토 범위가 있나?
- 기술 설명은 있지만, 그 흔적이 무엇을 입증하고 무엇을 아직 말할 수 없는지는 쉬운 말로 답했나?

## 짧은 추가 질문 목록

질문별로 **추가 질문 / 현재 답과 근거 / 남은 공백 / 다음 확인**을 기록한다.
왜 중요한지는 결론·확인된 영향·조사 범위를 어떻게 바꿀 수 있는지로 설명한다.
막연한 ‘더 조사 필요’ 대신 어느 원문·대상·기간에서 무엇이 보이면 답이 달라지는지 쓴다.
현재 근거만으로 답할 수 있는 편집 공백과, 실제 새 판별이 필요한 공백을 구분한다.

## 기존 조사 루프로 연결

- 답이 이미 원문에 있으면 기존 결과를 평가해 노트와 보고서를 보완한다. 새 수집을 반복하지 않는다.
- 열린 질문은 기존 note_id/current revision과 gap·mission을 재사용한다. 새로 중요한 질문이 생겼으면
  forsic_note에 현재 미확인 답·근거·next_checks를 저장한다. 질문만으로 침해 사실을 만들지 않는다.
- 판별이 필요하면 forsic-report-driven의 gap → mission → 기존 도구 수집/반환 재사용 → assess →
  현재 답 갱신을 따른다. 현재 사용자가 종합 조사를 승인한 범위 안에서 실행 가능한 것만 진행한다.
- 새 자료·권한이 필요한 검사는 무엇이 필요한지 남긴다. 자료 없음·시간초과·미평가는 부재의 증거가 아니다.
- 결과가 답이나 중요한 공백을 바꾸면 같은 snapshot의 두 보고서를 다시 render한다. 최종본 선택과
  Telegram 전달은 forsic-report-driven의 finalize 절차를 따르며 검토 중 초안은 첨부하지 않는다.

중요하고 실행 가능한 다음 확인이 없으면 남은 한계를 적고 끝낸다. 동일한 보고서로 추가 질문을
끝없이 재생성하지 않는다. 이 검토는 독자 관점 보완이며 독립 분석가 승인·조사 완결 증명이 아니다.
