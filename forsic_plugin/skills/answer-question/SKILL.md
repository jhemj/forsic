# 질문에 답하기

## 짧은 현황 답변

“지금 어디까지 확인했어?”에는 최신 노트와 실제 최근 작업 상태로 답한다. 과거 대화의
요약을 그대로 반복하지 않는다. 확인된 내용·아직 모르는 핵심·다음 확인을 짧게 말하며,
진행/일시정지/종료는 조사 내용과 구별한다. 알 수 없는 실행 상태를 추측하지 않는다.
사건 결론을 포함하면 review-conclusions의 짧은 검토로 중요한 인용 결과를 재사용해
대조한다. 답이 바뀌지 않으면 노트·보고서를 다시 만들지 않고, 상태 질문만으로 새 수집이나
멈춘 목표를 재개하지 않는다. 잘못된 이전 답을 찾으면 정정 사실과 근거를 알리고 아래
절차로 같은 질문의 현재 답을 고친다.

## 답변 저장·정정

사용자의 실제 질문에 먼저 답하고 핵심 주장에 실제 evidence_id를 인용한다.
중요한 질문의 답이 바뀔 때 바로 저장한다. answer에는 '확인 사실 / 현재 해석 / 아직
답하지 못한 부분'을 구별한다. forsic_note action=save에 question, answer, evidence_ids,
status(answered/open/needs_input), 필요한 alternatives, gaps, critical_gaps,
next_checks, timeline을 넣는다. critical_gaps는 그 질문의 결론을 바꿀 수 있는 미해결
검사만 적는다. 모든 한계를 핵심 공백으로 만들지 않는다. 같은 질문 정정은 get으로 읽은
기존 note_id와 **현재 revision**을 보내고 correction_reason을 적는다. 예를 들어 현재 revision이
2이면 저장 요청에도 2를 보낸다. 다음 버전 3은 저장 성공 후 도구가 부여한다. 충돌하면 다시
get하여 최신 내용과 합치며, 실패한 저장을 저장 완료라고 말하지 않는다. 새 질문은 새 노트다.
인사에는 노트가 필요 없다.
웹의 조사 보드는 이 노트를 그대로 읽는다. 카드용 HTML이나 별도 요약 문서를 중복 생성하지
않는다. question은 사람이 이해할 질문, answer는 현재 답, alternatives는 경쟁 설명,
gaps/next_checks는 남은 확인으로 구분한다. 중요한 발견을 채팅에만 두지 말고 근거 ID와 함께
저장한다. 시간순 관계가 답에 중요하면 correlate-time에 따라 같은 노트의 timeline을 채운다.
시각이 없으면 억지로 만들지 않는다. 시각화나 노트 저장 자체는 주장 검증이 아니다.
list/get으로 기존 결과를 재사용한다. 노트 자체를 원문 증거로 인용하지 않는다.
자료가 쌓이면 list의 query로 질문을 검색하고 next_offset으로 이어 읽는다. 공용
장기기억에 사건 원문을 복사하지 않는다. 원문은 자료 저장소, 답변은 사건 노트에 둔다.
요청에 답했으면 멈춘다. 추가 조사가 필요하면 구체적인 검사·예상 관측·필요 자료를
next_checks에 적는다. 삭제나 차단 등 대응 조치를 증거 확인 검사와 혼동하지 않는다.

답의 강도는 원문이 보여 주는 동작까지다. 검색·삭제·설치 명령이 기록된 것과 그 검색 결과·
삭제 성공·설치 완료는 다르다. 의심은 가설로 설명하고, 성공이나 귀속을 판별할 다음 확인을
붙인다. 원문 ID가 존재하거나 노트가 저장됐다는 이유로 해석이 검증된 것은 아니다.
정정 시 제목·요약·시간축·반론도 같은 답에 맞춰 고친다. 이전 노트와 보고서는 보존하고,
수정된 현재 답으로 새 보고 버전을 만든다.
