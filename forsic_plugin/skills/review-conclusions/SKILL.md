# 결론 검토

## 짧은 답변에도 적용

상태 질문에 답할 때도 이전 노트나 답변은 해석 후보이지 새 증거가 아니다. 답에 포함할
핵심 결론만 보존된 실제 결과와 대조한다. 설정/명령, 관측된 실행, 실행 효과, 사람의 신원,
현재 상태 중 원문이 어디까지 보여 주는지 확인한다. 이미지에서 관측한 시점의 상태를
지금 가동 중인 시스템 상태로 옮기지 않는다. 실행·성공을 직접 보여 주는 결과가 있으면
그 범위에서는 분명히 말하고, 없는 연결만 미확인으로 남긴다.

이 짧은 검토에는 별도 모델 호출·새 수집·보고서 생성이 필요하지 않다. 강한 표현을
완곡한 단어로만 바꾸지 말고, 예를 들어 “작업이 실행 중” 대신 “예약 설정이 있으며
실제 실행 여부는 아직 확인하지 못함”처럼 확인 대상과 남은 연결을 설명한다.
미검토 로그·읽지 않은 구간이 남아 있으면 이를 기록 부재나 이미지 전체의 조사 불가능으로
바꾸지 않는다. 다음 확인은 이미 가진 자료에서 할 수 있는 것과 외부 자료가 필요한 것을 나눈다.

## 보고·정정에 필요한 검토

보고서 작성 전 핵심 질문의 최신 노트를 모은다. 관측 사실과 가설을 구분하고,
판단을 바꿀 수 있는 반론·미검토 범위를 포함한다. summary를 findings보다 강하게 쓰지 않는다.

1. 각 핵심 문장을 실제 반환 결과와 검사 입력에 대조한다. 다음은 특히 혼동하기 쉽다.
   - 검색 명령 안의 단어는 검색에 걸린 내용이 아니다. 결과 본문을 읽고 무엇이 발견됐는지 적는다.
   - 삭제·패키지 명령은 시도 기록이다. 성공 응답·전후 상태 등 효과 근거 없이 성공으로 쓰지 않는다.
   - 경로 not_found는 확인한 파일시스템 범위의 미발견이다. 과거 존재나 삭제 원인을 입증하지 않는다.
   - 예약 설정은 실행 기록이 아니다. 실제 호출·프로세스·산출물과 연결되는지 확인한다.
   - 같은 IP·계정만으로 정상 관리자나 동일 행위자라고 하지 않는다. 정상 운영 설명도 검증 대상이다.
   - 가까운 시간만으로 같은 공격 세션을 만들지 않는다. 시각 출처·정밀도·시간대와 연결 근거를 본다.
   - 로그 파일명·수정 시각은 본문 기간이 아니다. 목록만으로 특정 기간의 기록 부재를 확정하지 않는다.
2. 가설은 버리지 말고 확인 사실과 구분한다. 결론을 바꿀 공백에는 다음 판별 미션을 붙인다.
   이미 반환된 결과의 평가가 필요하면 재수집부터 하지 않는다. 불가능한 검사는 필요한 자료와
   한계를 남긴다. 모든 불확실성을 해결하려고 조사를 무한히 늘리지 않는다.
3. 별도 문맥의 조언이 필요하면 forsic_reporting(state)의 현재 snapshot_id로
   forsic_reporting(action=review, snapshot_id=...)를 호출한다. 검토 입력은 현재 답·근거에서
   만들어지며 과거 형식의 snapshot을 따로 작성하지 않는다. 반환된 review_id, input_snapshot_id,
   review_status를 확인한다. 입력이 크면 핵심 질문별 노트로 나누어 question_ids로 필요한 질문을
   선택한다. 원문·반론을 잘라 통과시키지 않고 검토하지 않은 질문을 남긴다. 검토 실패·시간초과·
   미실행은 검토 통과가 아니다. 전달 여부가 불명인 요청을 그대로 자동 재전송하지 않는다.
4. 조언을 원문과 대조해 맞는 지적만 현재 노트·평가·시간축에 반영한다. 사실관계가 바뀐 초안만
   다시 검토하고 동일 초안을 반복 제출하지 않는다. 검토자 확신 자체는 새 증거가 아니다.
5. 새 보고는 forsic-report-driven에 따라 forsic_reporting(state/gaps)를 다시 읽고 render한다.
   검토 기록은 선택 인자 review_id로 연결한다. 노트·근거 내용이 바뀌면 옛 검토는 stale이며
   현재 답에 대한 승인이 아니다. 턴 번호만 바뀌면 같은 자료의 검토를 재사용한다. 새 자료를 검토하거나 그 한계를 남겨
   부분 보고를 만든다. 조언을 받았다는 것만으로 의미 검증 완료 상태를 만들지 않는다.
   과거 호환 보고서와 섞어 두 경로로 생성하지 않는다. 정정본은 새 버전이며 이전 파일을 보존한다.
   핵심 공백·무결성 미완료·검토 미완료를 양쪽 보고서와 전달문에 남긴다. 검토 실패만으로
   유용한 부분 보고를 막지는 않되, 네 파일 생성이나 실행 종료를 종합 조사 완료로 쓰지 않는다.

검토는 조언이다. 출처 ID가 존재한다는 것만으로 해당 문장이 입증되는 것은 아니다.
검토 모델도 틀릴 수 있으므로 특히 부재·실행 성공·행위자 귀속은 원문과 범위를 확인한다.
