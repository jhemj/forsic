# 결론 검토

사용자에게 전달할 중요한 주장과 변경된 판단에 집중한다. 검토는 분석 판단을 없애는 절차가 아니다.
직접 증거가 없더라도 test-hypothesis의 비교가 뒷받침하면 가장 유력한 해석을 제시한다.
현재 문맥에 정확한 원문이 있으면 재사용하고, 없거나 인용·해석이 의심되면 forsic_reporting(source)의
필요한 필드만 확인한다. 모든 정상 종결 항목을 다시 열거나 매번 새 모델 검토·수집을 요구하지 않는다.

## 관측과 분석 판단을 각각 검토

- 관측: 실제 근거 ID·대상·기간·줄/필드에 해당 값이 있는가? 요청 속성과 반환 속성을 구별한다.
  원문 인용·숫자·경로·시각은 그대로 대조한다. 기억이나 요약에서 문장을 복원해 인용하지 않는다.
- 분석 판단: 어떤 관측을 어떤 가정으로 연결했는가? 독립 단서가 현재 설명을 다른 설명보다 더 잘
  지지하는가? 가장 강한 현실적 반론과 출처/보존 한계를 반영했는가? 그 이유에 맞는 신뢰도인가?
- 적용 범위: 기능·실행·효과·승인·행위자를 구분했는가? 범위 한정 정상 판단이 다른 동작까지
  확대되거나, 미검토가 부재로 바뀌거나, 유력한 추론이 확인 사실처럼 제목에 쓰이지 않았는가?
- 현재 답: 가장 유력한 설명과 근거·신뢰도·중요 한계를 먼저 전달한다. 모든 문장을 '확인 불가'로
  바꾸거나 무관한 한계를 반복하지 않는다. 판단을 바꿀 반증이나 재검토 조건을 짧게 보존한다.

정상·악성 모두 같은 비교 기준을 쓴다. 승인 자료가 없다는 이유만으로 악성이라고 하지 않고,
정상 설명이 가능하다는 이유만으로 정상이라고 하지 않는다. 여러 정황의 설명력은 평가하되 같은
가정에 의존한 단서들을 독립 근거로 중복 계산하지 않는다. 문구·인용 개수만 바뀌면 신뢰도는 늘지 않는다.

## 과잉 단정과 과도한 보류를 함께 고치기

명령 기록은 실행/성공 영수증이 아니다. 설정·잔존 효과·독립 실행 흔적이 함께 지지하면 실행을 유력한
추론으로 말할 수 있으며, 확인된 부분과 추정 연결을 명시한다. 실제 없는 반환값·성공 로그를 쓰지 않는다.
필드 누락·미상 시간대·미확인 신원은 미확인으로 유지한다. 시간 근접은 자동 인과가 아니며 시각의
원래 의미와 correlate-time의 출처 연결을 지킨다. 프로그램명·내부 주소는 기능·승인을 보증하지 않는다.

검색 무결과는 실제 검사 범위의 결과다. 로그 보존/취득 공백과 상충 정황을 비교해 현재 해석을 내릴 수
있지만 공백 자체로 삭제·행위자·의도를 확정하지 않는다. 'A가 입증되지 않음'은 반대 A의 확인이 아니다.
추론의 중요한 연결이 약하면 신뢰도를 낮추거나 설명을 보류한다. 직접 증거 부재만으로 서로 설명력이
다른 가설을 같은 순위로 되돌리지는 않는다. 자료로 구별되지 않는 경우에는 그 자체를 정직하게 답한다.

## 정정·전달

잘못된 답은 바뀐 주장·이유·근거를 먼저 설명한다. 같은 질문의 note_id/current revision으로 정정하고
저장 성공을 확인한다. 충돌하면 최신 노트를 읽어 다른 변경을 보존한다. 저장 영수증은 해석 승인과 다르다.
제목·요약·시간축에도 같은 신뢰도와 범위를 적용한다. 새 답이 채팅에만 있고 저장에 실패했다면 이전
보고서를 새 결과처럼 제시하지 않는다. 원문과 과거 버전은 보존한다.

노트가 바뀌면 forsic-report-driven의 실제 결과 평가·state와 대조하고 최신 snapshot으로 render한다.
선택적 review는 조언이며 미실행·실패·stale는 통과가 아니다. unchanged 보고서를 반복 생성하지 않는다.
조사 종료와 판단 확실성은 구별한다. 중요한 미시도·미평가·차단을 숨기지 않고 실제 범위 충족 여부와
남은 불확실성을 각각 알린다. 예산 소진은 결론 강화의 이유가 아니다. 상태 질문만으로 조사를 재개하지 않는다.
