# 자료 탐색과 단서 추출
실제 디렉터리를 확인한 뒤 질문에 필요한 자료를 선택한다. 접속은 인증 로그,
예약 실행은 cron·systemd 설정과 실행 로그, 명령 흔적은 셸 기록과 실행 결과를 살핀다.
E01 내부는 forsic_image_files의 list/search/read를, 추출된 파일은 forsic_search/read를
사용한다. search에 file_path와 text, 필요하면 recursive를 지정한다. 결과의 생략 범위와
다음 페이지를 확인하고 중요한 주장은 검색 줄 주변 원문까지 읽는다. 긴 줄은 read_bytes로
이어 읽을 수 있다. 파일 경로가 없으면 상위 목록에서 실제 이름을 찾는다.
검색의 next_cursor가 있으면 동일한 path/text/recursive와 cursor로 이어 검색한다. 파일 한 개의
중간에서 끊길 수도 있다. 처음부터 같은 검색을 반복하지 않는다. 건너뛴 파일·구간·형식은
확인하지 못한 범위로 남기며 반환 건수를 전체 일치 건수로 쓰지 않는다.
설정·시도·성공·승인·귀속을 구별한다. 경로만으로 제품이나 악성 여부를 확정하지 않는다.
중요한 발견은 forsic_note에 근거와 함께 저장하고 질문에 답할 수 있으면 무작정 순회하지 않는다.

## 목록의 분류와 신뢰 판단을 분리

초기 분류는 어디를 조사할지 정하는 가설이다. 영향·판별 가능성에 따라 조사 깊이를 선택한다.
내용·범위·반론을 검토해 정상 설명이 충분하면 forensic-investigation에 따라 범위를 종결할 수 있다.
초기 분류만으로 종결하지 않으며 이후 반증이 나오면 필요한 범위를 다시 연다. 익숙한 제품명·프로세스명·디렉터리명,
내부 주소, 정기적 활동은 정상 운영과 양립하지만 신뢰·승인·무해성을 입증하지 않는다.
이름과 실제 객체의 동일성, 수행 기능, 사용 맥락, 승인 여부를 구별한다. 질문에 중요한
판별이면 실행 경로·명령행·파일 내용·연결 상대의 역할 등 현재 도구로 확인할 수 있는
근거를 선택한다. 모든 객체를 일괄 검사할 필요는 없고 중요한 미검증 대상을 남긴다.

네트워크 목록은 관측 시점의 주소·포트·상태다. 주소 대역은 통신 목적이나 상대의
신뢰성을 뜻하지 않는다. 연결의 방향·프로세스·기능·기록 범위를 확인하기 전에는
주소 분류만으로 악성 통신을 확정하거나 배제하지 않는다. 과거 스냅샷에 보이지 않는
연결도 조사 범위 전체에서 없었다고 확장하지 않는다.

부분 목록을 읽었으면 반환된 행 범위와 next_line/next_cursor를 기록한다. 전체·유일·
부재 주장이 필요한 질문은 필요한 나머지 범위를 읽거나 그 주장 범위를 줄인다.
출처가 보여 주지 않는 조직 역할·배포자·승인 사실을 파일명이나 계정명으로 채우지 않는다.
