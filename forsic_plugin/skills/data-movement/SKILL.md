# 자료가 실제로 밖으로 나갔는가

외부 통신이나 반출 질문에 답할 때 현재 자료에서 구별 가능한 명제를 고른다.
대상 파일/데이터 → 복사·압축 → 전송 시도 → 연결/전송 성공 → 실제 내용의 순서가 항상 모두
보존되는 것은 아니다. 비어 있는 단계를 서술로 메우지 않는다.

관련 파일·명령 기록, 애플리케이션 작업 로그, 인증/전송 세션, 보존된 프록시·방화벽·플로우 기록을
필요한 범위에서 읽는다. 같은 세션·대상·기간을 연결하고 누락/회전/샘플링 범위를 확인한다.

- 설정이나 셸 명령은 실행 성공이 아니다. DNS 조회는 연결 성공이 아니며, 허용된 연결은 파일 전송
  완료나 개인정보 유출을 입증하지 않는다. 응답 상태·작업 종료·실제 송신량을 따로 확인한다.
- 송수신 방향, 재전송·압축·프로토콜 부가량을 고려한다. 네트워크 바이트 수를 유출 파일 크기나
  개인정보 인원 수로 바꾸지 않는다. 내용을 연결하지 못하면 전송 내용은 미확인이다.
- 정상 백업·배포·동기화도 같은 도구와 목적지를 사용할 수 있다. 승인된 작업 기록, 평소 실행 패턴,
  대상 파일과 계정의 차이를 판별한다. 프로그램 이름으로 정상/악성을 고정하지 않는다.
- 검색 무결과는 검사한 파일·구간에서의 결과다. 큰 로그는 next_cursor로 이어 읽거나 남은 범위를
  명시한다. 지원하지 않는 PCAP/DB/압축 형식은 해석한 척하지 않는다.

주소·해시는 로컬 지표 목록에, 사건 시각은 원문 시간축에 연결한다. 발견 주소 접속·파일 업로드는
하지 않는다. '확인한 전송 단계 / 대상·방향 / 실제 내용 연결 / 정상 설명 / 남은 확인'을 노트에
저장하고 답을 바꿀 다음 검사만 기존 report-driven 미션으로 연결한다. 대응 결정은 사람에게 남긴다.
