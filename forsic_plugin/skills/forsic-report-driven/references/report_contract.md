# Forsic 보고서 기반 조사·미션 설계 명세

버전: `forsic-report-driven-1.0`  
성격: 신규 보고서·에이전트 계약 설계. 기존 제품에 적용·배포됐다는 의미가 아니다.  
적용 제품: Forsic / 안내자: 포식이 / 조사 실행 루프: Hermes  
산출물: 임원용 HTML·Word, 실무자용 HTML·Word, 공통 판단 스냅샷, 배포 manifest  
기본 독자: 의사결정자와 조사 실무자. 사건 정답을 미리 가정하지 않는다.

## 0. 기존 요구에서 유지한 부분과 이번에 추가한 부분

기존 공개 계약 `ko-dual-report-1`은 임원용 A4 2~3쪽과 실무자 상세, 같은 발견 번호·판단·근거·한계, 동일 블록을 HTML/Word로 렌더링, 실제 조치와 권고 분리, 원문 패키지 제한 배포, 정정·과거 파일 보존을 요구한다. 본 설계는 이를 유지한다. 중요 한계를 보존하기 위해 필요하면 임원용도 3쪽을 넘길 수 있다는 예외도 유지한다.

새로 추가한 부분은 보고서 요구사항을 조사 질문·공백·미션에 연결하는 구조, 조건부 적용성, 보고서 준비도와 조사 완료의 분리, Hermes skill, 필드별 작성 계약, 완료·재개·검증 기준이다. 이들은 현재 코드에서 확인된 구현이 아니라 본 패키지의 제안이다.

이 문서는 기존 두 독자 보고 요구를 포함하는 설계 참조다. 삭제된 이전 저장소나 비공개 인계 자료를 읽을 필요는 없다. 현재 제공되는 도구와 호출 계약은 같은 폴더의 `tool_contracts.md`, 실제 연결은 `forsic_plugin/report_driven/`을 기준으로 확인한다. Hermes의 `SKILL.md` + `references/` 형식으로 필요한 절차를 읽는다.

## 1. 핵심 원칙: 보고서 완성은 정답 문장을 채우는 일이 아니다

목표는 “모든 칸을 채우고 공격을 입증한다”가 아니다. 다음을 달성해야 한다.

1. 사용자의 중요한 질문에 현재 증거가 허용하는 답을 제시한다.
2. 사실·해석·가설, 검토 상태·판단 상태를 구별한다.
3. 중요한 반론·정상 대안과 미검토 범위를 보존한다.
4. 답을 바꿀 수 있는 실행 가능한 검사를 수행하거나, 수행할 수 없는 이유를 설명한다.
5. 읽기 쉬운 두 독자용 보고서를 같은 판단 묶음에서 만든다.

“미확인”은 유효한 답일 수 있지만 자동 완료값은 아니다. 미확인이어야 하는 근거와 범위, 이미 시도한 검사, 아직 가능한 검사가 있는지까지 있어야 한다. 반대로 최초 유입·행위자·승인 기록이 증거에 없다고 무한히 조사해서도 안 된다.

### 역방향 편향 방지

보고서의 제목이나 문장이 원하는 결론을 정하지 않는다. “침투 경로” 섹션이 있다는 이유로 침투를 전제하지 않고, “최초 관측·유입 가능성”처럼 증거 수준에 맞춰 표현한다. 피해·유출·공격자 귀속·정상 승인도 해당 명제를 지지하는 자료가 있을 때만 채운다. 양성 발견뿐 아니라 정상 설명 강화·반론 확인·근거 있는 판별 불가도 조사 성과다.

## 2. Hermes와 Forsic의 책임

Hermes가 단일 모델·도구 실행 루프, 다음 미션 선택, 필요한 절차 참조, 대화 압축과 사용자 상호작용을 소유한다. 보고서 시스템은 두 번째 Controller·무한 재호출 루프·자율 복구 에이전트를 추가하지 않는다.

Forsic은 읽기 전용 포렌식 도구, 안정적 증거 참조, 검사·실행 결과 보존, 채택·정정, 보고 공백 투영, 결정적 렌더링과 배포를 제공한다. 에이전트는 도구 결과를 근거로 좁은 주장을 제안하고, 호스트가 기계적 범위·버전·인용·실행 경계를 검증한다.

Jev가 있으면 적격한 미션·입력 묶음·검토 경로 사이에서 의견을 줄 수 있다. Jev는 사실 승인, 필수 반론 삭제, 보고서 완료, 권한 확대, 침해 확정을 결정하지 않는다. 일반 LLM·Jev 성능이 검증됐다고 이 템플릿이 주장하지 않는다.

## 3. 세 가지 산출물과 세 가지 상태

### 산출물 계층

- **조사 상태**: 원본·관측·주장·질문·가설·검사·미션·실행·반론의 현재 상태와 이력.
- **보고 스냅샷**: 특정 기준시점에 호환되는 객체 버전을 고정한 배포 후보. 원장을 다시 해석하지 않는다.
- **독자용 보기**: 같은 스냅샷의 임원용·실무자용 내용 선택. HTML과 Word는 같은 reader view를 사용한다.

### 상태의 독립성

| 축 | 권장 값 | 금지되는 해석 |
|---|---|---|
| 실행 | 진행 / 정상 정지 / 예산 종료 / 오류 / 사용자 중단 | 프로그램 종료 = 조사 완료 |
| 조사 범위 | 조사 중 / 자료 대기 / 일부 검토 / 지원 범위 종결 | 질문 일부 해결 = 사건 전체 규명 |
| 보고서 | 초안 / 부분 스냅샷 / 범위 종결 보고 / 배포 승인 | 파일 생성·해시 성공 = 의미 정확성·배포 승인 |

품질 상태도 별도다. schema 검사, 출처·버전·literal 검사, 의미 표본 검토, analyst oracle 평가, 페이지·접근성 검사를 각각 표시한다. “검증 완료”라는 단일 표현으로 합치지 않는다.

## 4. 공통 문서 디자인

### 4.1 디자인 토큰

| 항목 | 규격 |
|---|---|
| 종이 | A4 세로. 임원 2~3쪽 목표, 기본 제공 양식 3쪽 |
| 여백 | 좌우 18~20mm, 상하 17~20mm |
| 글꼴 | Noto Sans CJK KR, 대체 Malgun Gothic. 폰트는 패키지에 포함하지 않음 |
| 제목 | 20~22pt, 검정, 짧은 명사형 |
| 1차 제목 | 12.3~14pt, 검정·굵게 |
| 본문 | 10.3~11pt, 줄간격 1.15~1.35 |
| 표 | 9.5pt 권장, 최소 가독성 아래로 임의 축소 금지 |
| 주석 | 8.5~9pt. 중요한 한계를 주석에만 숨기지 않음 |
| 색 | 흰 종이·검정 본문·회색 배경 및 얇은 선. 위험을 색만으로 표시하지 않음 |
| 표 너비 | 본문 폭 이내, 머리글 반복, 긴 문자열 줄바꿈 |
| 머리말 | Forsic / 보안등급·배포 범위 |
| 꼬리말 | 보고서 ID·스냅샷 식별·독자·쪽 번호 |
| 문장 | 한국어 업무보고체. 사실은 짧고 명확하게, 해석은 한정어를 보존 |

캐릭터는 조사 UI의 안내자다. 정식 보고서 본문에 큰 캐릭터·대화체·진행 애니메이션을 넣지 않는다. 표지 없이 첫 페이지에서 답을 읽게 한다. 기관 로고가 필요하면 승인된 로컬 자산만 추가한다.

### 4.2 정보 우선순위

임원용은 현재 답·확인된 영향·불확실성이 먼저다. 경영 판단·대응 권고는 사람이 하며 새 보고서에서 작성하지 않는다. 실무자용은 질문·근거·판별·반론·공백·재현 경로가 먼저다. 기술 ID·원문 전체·토큰·실패 로그는 임원용 기본 화면을 차지하지 않게 한다. 그러나 중요한 입력 차단·미평가·내부 결함이 결론을 제한하면 요약에 명시한다.

### 4.3 길이 조절

임원용 2쪽 구성은 1쪽의 핵심 판단·영향·주요 발견과 2쪽의 경과·반론·조치·공백을 합쳐도 중요 한계가 유지될 때만 사용한다. 기본 3쪽의 3쪽은 조치·다음 미션·기준을 담는다. 발견을 세 개 채우기 위한 중복은 금지한다. 상위 발견 표시 수는 편집 상한일 뿐 조사 가설·증거 수 제한이 아니다.

실무자용 12쪽은 **빈 양식의 구성 예**다. 조사 결과가 적으면 축약하고, 많으면 발견·검사·증거 부록을 반복한다. 길이 상한으로 원문·반론·검사 결과를 삭제하지 않는다. 본문은 핵심 재구성을 유지하고 세부는 탐색 가능한 부록으로 분리한다.

## 5. 임원용 보고서 작성 계약

### E01 — 핵심 판단과 영향

**답해야 할 질문:** 무엇이 확인됐고, 무엇이 아직 확인되지 않았는가?

필수 내용은 사건·보고서 식별, 기준시점·범위, 한 문장 결론, 확인 사실·해석·미확인, 대상·업무 영향, 주요 발견이다. 수신·파싱·모델 호출 수를 요약의 주요 성과로 쓰지 않는다.

권장 결론 문형:
> [확인한 사실]은 [대상·기간·증거 범위]에서 확인하였음. [가능한 설명]으로 해석되나 [중요한 반론·공백]으로 [더 강한 결론]은 아직 판별하지 못하였음. 이를 구별할 추가 조사는 [자료·검사]임.

사건상 의미가 없는 메타데이터는 주요 발견으로 올리지 않는다. 정상 설명이나 반증이 결론을 크게 바꿨다면 상위 발견으로 제시한다.

**다음 미션 발생:** 실행 성공·확산·영향이 결론을 바꾸며 현재 반환 결과로 판별 가능한데 미평가인 경우. 단순히 요약 문장이 덜 매끄러운 경우는 편집 작업이며 새 포렌식 조사가 아니다.

### E02 — 경과·경쟁 설명·중요 한계

**답해야 할 질문:** 어떤 근거 사슬로 결론을 냈고, 어디가 아직 연결되지 않았는가?

핵심 시간축, 설명 비교, 조사 범위·중요 공백을 담는다. 기록상 선후와 사건 인과를 구별한다. 시각 미상·비교 불가의 중요한 사실도 포함한다. 승인된 작업이라는 설명도 승인 자료나 근거가 없으면 사실로 쓰지 않는다.

**다음 미션 발생:** 서로 다른 객체를 같은 객체로 연결했을 가능성, 반론 미검토, 결과와 조건의 연결 공백, 시각 불확실성 때문에 결론이 달라지는 경우. 모든 파일시간을 정밀 분석하기 위한 미션은 자동 생성하지 않는다.

### E03 — 확인된 수행 조치·남은 조사

**답해야 할 질문:** 실제 수행 기록은 무엇이며, 미확인 답을 위해 어떤 자료를 더 조사할 것인가?

수행한 조치는 실행 기록을 요구한다. 경영 의사결정·대응 권고를 작성하지 않는다. 계획·권고를 실행 사실로 표현하지 않는다. 대응 내역이 없으면 “수행 여부 미등록”이라고 적는다.

추가 자료 요청은 질문·공백·현재 능력의 한계에 연결한다. 내부 참조 오류·잘못된 도구 선택을 자료 요청으로 바꾸지 않는다. 다음 미션은 우선순위가 높은 몇 건만 요약하며 전체 목록은 실무자용에 둔다.

**배포 조건:** 중요한 한계·정정·미평가가 요약에서 누락되지 않아야 한다. 승인자가 지정되지 않았으면 승인된 보고서처럼 표시하지 않는다.

| A01 조사 개요·현재 답 | 최초 질문, 승인 범위, 현재 답 매트릭스, 변경된 범위 | 실행·보고 상태와 질문 답을 분리 |

| A10 검사·복구·비용 | 물리 결과·논리 평가·채택·전달상태, 원의무 복구 | 응답 수신·재분류·국소 보류를 복구 성공으로 계산 금지 |
| A11 조치·공백·미션 | 실행 사실/권고, gap→미션, 권한·예산·재개 조건 | 외부 자료가 실제 필요한 경우만 요청 |
| A12 근거·정정·배포 | 정확 locator/span, 근거 계보, 보고 manifest, 과거 파일 | 원문 패키지 제한 배포, 정정된 과거 파일 불변 |

### 발견 상세의 원자성

한 발견에 서로 독립적인 명제가 있다면 주장 ID를 나눈다. “명령이 기록됐다”, “프로세스가 시작됐다”, “작업이 성공했다”, “승인되지 않았다”, “공격자가 실행했다”는 각각 다른 증거 요구를 가진다. 여러 명제를 한 제목으로 묶더라도 제목이 가장 강한 미입증 명제를 암시하면 안 된다.

인용은 정확하되 의미 검증과 구별한다. literal 일치는 원문 존재의 검증이고 인과·목적·악성의 타당성 보증이 아니다. 제목·핵심 요약도 원자적 주장 참조를 가져야 한다.

## 7. 보고 요구사항 카탈로그

`section_catalog.yaml`은 섹션별 필수 질문·허용 공백·미션 트리거·종결 기준을 담는다. 다음 원칙으로 적용한다.

- 공통 필수: 사건 질문·범위·증거 상태·현재 답·주요 근거·반론·공백·조치 구분·출처·정정.
- 조건부 필수: 유입·권한·지속성·실행·통신·유출·복구 등은 사용자 질문, 발견, 반론, 실제 범위에 따라 활성화.
- 관련성 미평가: 자동 N/A가 아니다. 짧은 적용성 검토 또는 범위상 이유를 남긴다.
- 적용 안 됨: 합의 범위·사건 질문·검토 결과로 이유를 설명하고 근거 참조를 남긴다.
- 범위 변경: 새 승인·범위판으로 기록한다. 보고서 완료율을 높이려고 기존 의무를 조용히 삭제하지 않는다.

새 단서가 기존 카탈로그 밖의 질문을 요구하면 질문과 요구사항을 확장한다. 카탈로그는 가설 개수·공격 경로를 고정하지 않는다.

## 8. 보고 공백의 종류

| kind | 뜻 | 기본 처리 |
|---|---|---|
| unassessed_result | 결과가 반환됐지만 논리 평가가 없음 | 정확 조건·결과판으로 평가 |
| unpresented_source | 보존 원문이 있지만 현재 입력에 제시되지 않음 | 필요한 exact span 회수 |
| missing_evidence | 필요한 자료가 취득되지 않음 | 판별 가치를 설명하고 최소 자료 요청 |
| unsupported_tool | 현재 능력으로 관측할 수 없음 | 승인된 대체 도구·범위 또는 공백 종결 |
| internal_error | 참조·계약·파서·컴파일 등 내부 결함 | 내부 수리 경로. 외부 자료 부족으로 분류 금지 |
| contradiction | 중요 반론·상충 미검토 | 양쪽 원문을 보존한 비교 |
| untested_alternative | 중요한 경쟁 설명의 예측을 미검사 | 판별 가능한 경우 검사 설계 |
| identity_uncertainty | 대상·세션·행위 identity 미해결 | 명시적 객체 연결 또는 범위 제한 |
| time_uncertainty | 시각 의미·순서가 결론에 영향 | 근거 있는 정합화·비교 또는 미상 보존 |
| budget_deferred | 조사 가능하지만 예산상 미검토 | 완료로 세지 않고 미검토·재개 조건 |
| editorial_only | 문장·표·페이지·중복의 문제 | 모델 재조사 없이 편집 또는 제한 편집 요청 |
| publication_issue | 승인·마스킹·버전·파일 문제 | 배포 차단, 조사 사실은 보존 |

중요도는 impact(의사결정 영향), epistemic_state(지지 수준), work_state(처리 상태)와 구별한다. 미평가는 낮은 중요도를 뜻하지 않는다.

## 9. 다음 미션을 설계하는 루프

Hermes의 기존 대화·도구 루프 안에서 수행한다.

1. 현재 보고 스냅샷과 변화한 질문·결과·반론을 읽는다. 전체 원문과 전체 보고서를 매번 다시 읽지 않는다.
2. 보고 요구사항별 상태를 확인한다. 누락 필드와 조사 공백을 구별한다.
3. 새 반환 결과·반론·핵심 identity·판별 가능한 설명을 우선 후보로 만든다.
4. 각 후보에 질문, 원래 의무, 대상 명제, 정확 입력·범위, 도구 능력, 예상 판별 분기, 비용과 중단 조건을 붙인다.
5. 이미 평가한 동일 조건·결과는 재사용한다. 같은 결과의 다른 질문 평가에는 새 논리 사용 관계를 남긴다.
6. 실행 가능한 미션 사이에서 영향·판별 가능성·대기·전체 비용을 비교한다. Jev 의견은 선택 근거 중 하나이며 필수 반론을 밀어낼 수 없다.
7. 한 미션 또는 의도적으로 선택한 작은 독립 묶음을 수행한다. 읽기 전용 허용 도구를 사용한다.
8. 결과·제시 범위·계약을 검증하고 독립적으로 유효한 주장·평가만 채택한다.
9. 어떤 질문의 답·범위·반론·다음 행동이 바뀌었는지 기록한다. 무변화면 다음 반복에 같은 미션을 재생성하지 않는다.
10. 두 독자용 보고 뷰를 같은 스냅샷에서 갱신한다. 보고서 보기와 포식이 애니메이션은 조사 호출을 만들지 않는다.
11. 가능한 중요한 미션이 없거나 상한에 도달하면 한계와 미검토를 남긴 보고서를 생성한다.

미션을 고르는 목표는 보고서의 완성도 점수가 아니다. 예를 들어 미확인 표 하나를 빈칸 없이 채우는 것보다 중요한 반환 결과 하나를 정확히 판별하는 것이 우선이다.

## 10. 미션 카드의 완성 계약

필수 항목은 다음과 같다.

| 묶음 | 내용 |
|---|---|
| 식별 | mission ID, original obligation ID, gap ID, 질문·명제·보고 섹션 |
| 의미 | 현재 답, 왜 중요한지, 경쟁 설명·가정·판별 예측 |
| 입력 | 객체별 정확 버전, 결과판, 실제 제시 요구, 필수 반론 |
| 실행 | 필요 능력, 허용 도구, target identity·locator·범위, 실행 가능성 |
| 판별 | 지지·반박·판별 불가 조건, 부분 무결과의 의미 |
| 비용 | 호출·입력·출력·시간·자원 한도, 예산 출처, 기존 결과 재사용 |
| 반복 | 기존 시도와 차이, 물질적 변경, 실패 계보, 제한 재시도 |
| 완료 | 검증·채택 참조, 원의무 해결 범위, 미해결 의무·재개 조건 |

어떤 항목이 아직 없으면 임의로 채우지 않는다. 예산이 할당되지 않았거나 도구가 확인되지 않았으면 `draft/blocked`로 남기고 실제 실행 예정이라고 말하지 않는다.

### 판별 미션과 탐색 미션

탐색은 “어떤 자료를 찾는가”가 목적이며 found/no_match_in_scope/partial/unavailable을 기록한다. 탐색 원문은 좁은 사실을 지지할 수 있지만 그것만으로 가설 supports/refutes를 반환하지 않는다.

판별은 대상 명제에 실제로 관측 가능한 조건이 필요하다. 한쪽만 판별 가능한 검사도 허용하며 반대쪽은 null/unsupported로 명시한다. 양쪽 모두 불가능하면 판별 검사가 아니라 탐색·자료 요청·공백이다.

### 사후 평가

결과를 본 뒤 설계한 새 조건은 `after_result`로 기록한다. 기존 결과를 재사용할 수 있지만 사전 예측의 독립 검증으로 세지 않는다. 원래 계약·실패·질문을 소급 수정하지 않는다.

## 11. 보고서 준비도와 종료 게이트

단일 “100% 완료” 수치 대신 준비도 벡터를 사용한다.

- **내용 준비:** 해당 범위의 필수 섹션이 실제 답 또는 설명된 공백을 갖는다.
- **근거 준비:** 참조 closure, 객체판·결과판·주장판, 실제 제시·literal·범위를 검사했다.
- **조사 준비:** 현재 범위에서 가능한 중요한 미션·반론·반환 평가가 남는지 확인했다.
- **배포 준비:** 마스킹·승인·동일 manifest·네 파일·페이지·링크 검증을 확인했다.

### 종료 유형

| 종료 | 허용 상태 |
|---|---|
| draft_only | 제목·문구·근거 정합성·배포 검증이 미완료 |
| partial_publishable | 현재 유효 근거로 부분 보고 가능. 조사 공백·미검토·예산·실패를 본문에 표시 |
| scope_final_candidate | 정의한 범위의 필요한 검토를 마쳤고 남은 미확인의 이유·재개 조건을 명시. 승인 전 후보 |
| published | 기관 정책에 따른 검토·배포 승인을 포함해 파일을 발행 |

서로 다른 의미를 합치지 않는다. ‘자료가 없어 알 수 없음’은 적절한 범위 종결이 될 수 있다. ‘아직 평가할 결과가 있음’, ‘내부 오류로 못 함’, ‘예산 때문에 안 함’은 전체 조사 완료가 아니다.

### 가짜 완료 방지

기존 중요한 요구사항을 N/A로 바꾸기, scope를 몰래 좁히기, 미확인을 일괄 채워 종결하기, 미검토 반론을 본문에서 숨기기, output 파일 생성으로 완료 표시하기를 금지한다. 적용성·범위 변경에는 사유·원래 범위·새 근거·승인 상태가 필요하다.

## 12. 복구·무효화·캐시

복구는 `원의무 → 실패 → 실제 입력/방법 변화 → 유효 채택 → 원의무 해결 범위`로 연결한다. 새 mission ID나 같은 내용의 재작성은 진전이 아니다.

공통 실패는 영향 범위를 명확히 한다. 모델 연결 오류와 근거 검증 오류, 내부 참조 오류와 외부 자료 부재, 경로 해석 실패와 파일 삭제 증거를 구별한다. 전달 미상은 기존 요청·worker 결과를 먼저 조정하며 자동 재전송하지 않는다.

### 캐시

- 물리 결과: 증거·source run·도구·해석기·정확 대상 범위.
- 검사 해석: 고정 명제·조건·결과판·필수 근거·반론.
- 질문 답: 관련 주장·반론·공백·답의 범위.
- 보고서: 고정 스냅샷·독자 선택·편집 규칙·renderer.

화면 시각·제목만 달라졌다고 근거를 다시 분석하지 않는다. 새로운 파티션·다른 바이트·별도 발생·새 반론은 기존 캐시로 막지 않는다.

## 13. 자연어 편집 규칙

| 위험한 표현 | 사용할 표현 |
|---|---|
| 실행됐다 — 근거는 명령 문자열 | 명령 문자열이 기록돼 있다. 실행 결과는 미확인이다. |
| 공격자가 수행했다 — 근거는 계정 | 해당 계정의 세션·기록에서 확인됐다. 실제 사람은 미확인이다. |
| 외부 C2 통신 — 근거는 사설주소 명령 | 해당 주소를 대상으로 한 TCP 관련 명령이 기록됐다. 연결 결과·소속·용도는 미확인이다. |
| 파일이 삭제됐다 — 근거는 경로 조회 실패 | 지정한 이미지·resolver 범위에서 경로를 해석하지 못했다. |
| 정상이다 — 근거는 프로그램명 | 정상 사용 가능한 기능이다. 이번 행위의 승인·목적은 별도 확인이 필요하다. |
| 대응 완료 — 근거는 권고 | 대응을 권고한다. 실제 수행 여부는 미등록이다. |
| 로그 없음 → 행위 없음 | 정의한 검색 범위에서 해당 기록이 확인되지 않았다. 생성·보존·완전성 전제는 [상태]다. |

명칭·행위자·목적·성공·네트워크 범위 같은 제목의 의미 필드도 주장 근거에 연결한다. 임원용 압축에서 한정어와 부정어를 삭제하지 않는다.

AI의 내부 사고 전문을 보고서나 UI에 요구하지 않는다. 공개할 것은 검사 목적, 선택한 근거, 경쟁 설명, 판별 결과, 남은 공백이다.

## 14. 포식이와 보고서의 공통 설명

UI 설명은 별도 사실 생성 경로가 아니다. 보고서가 쓰는 같은 질문·평가·주장 참조에서 조립한다.

- 이전 결과: 무엇을 알았고 무엇은 여전히 모르는가.
- 현재 작업: 실제 상태, 대상, 왜 확인하는가.
- 판별 조건: 결과가 나오면 어떤 설명·명제가 바뀌는가.
- 복구: 무엇이 실패했고 어떤 입력·방법을 실제로 바꿨는가.

가공 예문:
> “앞서 명령이 기록된 것은 확인했어요. 지금은 대응 결과가 같은 작업에 속하는지 대조하도록 요청했고 응답을 기다리고 있어요. 연결되더라도 작업 승인 여부는 별도로 확인해야 해요.”

실제 요청이 없으면 ‘대조할 후보’, 입력만 등록되면 ‘입력 준비’, 모델 응답만 도착하면 ‘근거 검증 중’이라고 한다. 과거 작업 탐색이 현재 실행 상태·표정·색을 바꾸지 않는다.

## 15. 버전·출판·보안

보고서의 현재 참조는 같은 스냅샷에서 호환돼야 하지만 모든 객체 버전 숫자가 같을 필요는 없다. 질문 정의판, 검사판, 결과판, 답판, 표시판을 목적에 맞게 분리한다. 새 근거 때문에 기존 고정 검사 평가가 역사적으로 무효가 되는 것과 최신 답에 적용할 수 없는 것은 다르다.

수정은 `ReportDelta` 또는 호스트의 채택 명령으로 적용하고 이전 버전은 보존한다. 모델이 원장·템플릿·validator·완료 조건을 수정해 통과시키지 못하게 한다. JSON의 ‘adopted=true’는 권한 증명이 아니며 호스트의 채택 영수증이 필요하다.

HTML은 escape된 텍스트만 삽입하고 script·외부 asset·자동 URL 미리보기를 사용하지 않는다. Word는 내부 bookmark·링크를 검증하고 외부 관계·삽입 리소스를 배제한다. URL·명령 문자열은 증거 데이터이며 자동 실행하지 않는다.

배포본은 마스킹된 보기이고 원문 저장소는 변경하지 않는다. 무표식 자격정보의 완전 탐지는 보장할 수 없으므로 실제 배포 승인 절차가 필요하다. 원문 포함 ZIP은 기본 보고서 패키지와 분리한다.

네 파일 생성은 임시 디렉터리에서 완료·검증한 뒤 manifest와 함께 원자적으로 등록한다. 현재 판단이 변경되면 그 이전 cutoff의 역사적 보고서로 발행 가능한지 정책에 따라 판단하고 최신으로 표시하지 않는다. 내보낸 과거 파일을 덮어쓰지 않는다.

## 16. 구현 인터페이스 제안

아래 이름은 Hermes 기본 도구 또는 현재 Forsic API가 아니다. 새 Forsic native tool adapter가 제공할 인터페이스의 예다.

| 인터페이스 | 역할 | 금지 |
|---|---|---|
| report_state_read | 현재 질문·답·공백·허용 참조·delta 읽기 | 읽기만으로 새 조사 발행 |
| report_gap_audit | 요구사항·근거·반론·미평가 상태 계산 | 스스로 의미 정답을 단정 |
| report_mission_record | 선택한 미션 초안과 근거·조건 기록 | 기록을 실제 발행으로 표시 |
| evidence_read / test_execute | 승인된 읽기 전용 범위의 실행·조회 | 발견 명령·주소 실행 |
| report_assessment_propose | 좁은 판단과 질문 변경을 제안 | 모델이 직접 채택·승인 |
| report_render | 고정 스냅샷으로 두 reader view와 네 파일 생성 | 렌더 중 새 사실 생성 |
| report_publish | 검증·권한·manifest 조건에 맞춰 발행 | approval 미제공을 승인으로 간주 |

기본 구조는 `reports.py` 또는 작은 report 모듈, 위 도구 adapter, Hermes skill이다. 별도 큐·메모리 플랫폼·외부 재호출 감독자를 만들지 않는다.

## 17. 평가·회귀·실제 E2E 수락

### 무모델 계약 시험

1. 빈 보고서가 완료로 판정되지 않는다.
2. 미확인이라도 판별 불가의 이유·범위가 있으면 부분 보고가 가능하다.
3. 중요한 반환 미평가·반론이 남으면 전체 범위 종결이 제한된다.
4. 후보 주장·Jev 의견이 사실·침해색·종결을 결정하지 못한다.
5. 같은 원문의 재사용이 독립 증거 수·발생 수를 늘리지 않는다.
6. 인용은 제시·canonical 두 경계와 실제 버전을 확인한다.
7. 내부 참조 오류를 외부 자료 요청으로 전환하지 않는다.
8. 새 결과의 늦은 채택·정정은 기존 보고서를 최신으로 유지하지 않는다.
9. 두 reader와 HTML/Word의 F-번호·판단·중요 한계가 일치한다.
10. 악성 HTML·외부 URL·명령 문자열이 실행·접속되지 않는다.
11. 200개 초과 근거·긴 경로·한글·표 넘침·동일 prefix ID 링크가 잘리지 않는다.
12. 렌더·열람·캐릭터 동작이 모델 호출을 만들지 않는다.

### 의미 평가

Analyst oracle은 사건 단위로 분리한다. 회수 가능한 중요한 근거, 필수 반론, 허용되는 좁은 판단, 합리적 다음 미션 집합, 판별 불가가 정답인 범위를 라벨링한다. 정답은 평가에만 쓰고 사건명·IOC·정상 이름을 구현에 넣지 않는다.

지표는 질문별 유효한 답·다음 행동 변화당 총비용, 반환→판별 지연, 미해결 의무의 연령, 중요한 근거·반론 누락, 오확정, 제목의 의미 과장, 불필요 반복, 사람의 개입 필요성이다. oracle 없이는 정확도·회수율·침해 확률을 산출하지 않는다.

### 실제 E2E

초기에는 보고 gap 도구와 mission skill을 보존 자료 재생에서 비교한다. 새 실제 실행은 동결 소스·모델·정책·시작 영수증·별도 디렉터리를 가진다. 보고 구조, queue, model, concurrency, budget을 한꺼번에 바꾼 실험은 통합 수락으로만 사용한다.

Qwen 운영 검증과 Luna 시험을 분리한다. Jev의 비용·메모리·fallback은 추가 비용에 포함한다. 임원용은 실제 DOCX 렌더링과 HTML 인쇄로 페이지 품질을 확인하며 실무자용은 원문 탐색 경로를 시험한다.

## 18. 에이전트에게 바로 전달할 작업 지시

“첨부한 report-driven skill과 section catalog를 읽고, 사건 질문·승인 범위·현재 근거로 보고 스냅샷을 초기화하라. 각 요구사항을 충족·미해결·조건부 미적용으로 분류하고 이유를 기록하라. 중요한 보고 공백 중 현재 도구와 자료로 판별 가능한 미션을 제안하라. 같은 결과·같은 조건의 반복을 피하고 새 반론·새 범위를 보존하라. 실행은 Hermes의 기존 도구 루프에서만 수행하라. 결과를 검증·채택한 뒤 질문의 답과 두 reader view를 갱신하라. 더 강한 결론을 얻기 위해 사실을 만들거나 원래 범위를 조용히 줄이지 말라. 예산·자료·능력 한계에 도달하면 원의무와 미검토를 남긴 부분 보고서를 생성하라. 배포 승인·원문 패키지는 별도 권한을 따른다.”

## 19. 패키지 사용 경계

동봉 Word·HTML은 실제 사건이 아닌 양식이다. `examples/`는 모두 합성 예시다. JSON schema는 구조를 검증하며 자연어 의미의 진실성을 증명하지 않는다. `reference/`의 도구는 네트워크·모델·증거 도구를 호출하지 않는다. Hermes skill은 방법 문서이며 제안한 Forsic native tool이 자동 설치·구현되는 것은 아니다.

미제공 정보는 실제 도구 목록과 권한, 원장 adapter, 운영 Qwen·Jev 검증, 기관 배포 승인, 사건별 판단·근거다. 실제 제품 통합 후 이 문서의 수락 기준으로 별도 검증해야 한다.
