# Current judgment before report writing

Use this reference after a material correction, a successful alternative to a failed tool, or a conflict
between the current answer and retained results. Reconcile through the existing question writer;
do not make a second analytical ledger or infer a conclusion from a successful tool return alone.

## Reconcile only what changed

Follow the returned `judgment_read_call` (or navigation `details_call`) for the selected question's
complete current judgment projection. Copy its child `read_call` and `next_call` with their question,
canonical pointer and snapshot intact; do not invent `/claims` or `/judgments` paths. Reuse unchanged
scalar reads from the same snapshot instead of rereading whole catalogs. This derived state is
navigation for reconciliation, not original source evidence.

For each consequential result, identify which existing proposition it supports, refutes or narrows,
which declared gap it resolves, and which limits remain. Read the current gap IDs and exact returned
scope, then save the answer, selected judgments and applicable gap dispositions atomically. Preserve
old failures as attempt history. A later success does not erase an unrelated failure or prove all
files, time periods, expressions or behaviors were examined. Do not retain an obsolete categorical
statement and merely append the correcting result in a closure reason or review response.

For an existing v2 question, save each ready independent report correction with `report_slot_updates`, using
the same row fields as `report_slots` and omitting unchanged rows. Only named declarations are rebound; untouched
rows retain their old basis/references and may need recheck after answer or claim changes. `report_slots` replaces
the entire array ([] clears it); do not supply both fields. New questions use `report_slots`. Open/active questions
can also save ready `gap_dispositions` incrementally. Do not wait for every gap or reread complete catalogs before
a ready save. Keep answer/claim changes and dependent corrections atomic when consistency requires it.

Use existing `judgment.claims` for distinct propositions with their own direct citations, scope,
counterarguments and limitations. A broad overall answer can summarize these claims. A limitation
on static capability does not negate an observed historical process record; an observed process
does not establish persistence, communication or exfiltration. Do not repeat the entire compound
answer as each claim. Repeated calls or derived views of one source are not independent corroboration.

For each unresolved material issue, state why it matters, what result would change the assessment,
why that check remains unperformed and the next useful action/reopening condition. Distinguish
missing material, unsupported tool, partial coverage, permission needed, budget deferral and a
completed scoped search with no match. Missing external-reputation credentials do not prevent
already-authorized local static analysis. Investigate useful alternatives within the existing scope;
never turn an unsupported attempted action into a claim that the whole question is impossible.

## Keep time and action separate

Separate event time, record/capture time, image acquisition time and analysis time. State the actor
as supported (attacker, administrator, automation or unknown), and preserve competing explanations.
File state-change metadata does not alone establish installation, concealment or timestamp tampering.
Do not label an administrator's recovery window as initial intrusion solely because both concern the
same file. A historical process snapshot supports that captured state under its authenticity/time
assumptions; it does not establish the state at later image acquisition or of a currently running host.

## Answer the actual report question

Personal-data possession requires observed data types/locations or an explicit unexamined scope.
Distinguish possession, access by an actor/process and external transfer. Malware presence does not
answer those questions. Describe what retained code/strings suggest and why it matters, while keeping
static candidates, implemented capability and actual use separate. Acknowledge a supported partial
answer instead of reverting all related findings to a blanket unknown.

## Compare the assembled version

Write from the current question projection, selected atomic claims, actual sources, current limits and
timeline. Old conversation/closure/reviewer text is navigation, never a replacement for the current answer.
Compare summary, body, technical appendix and their direct citations under the same version. Reference
existence/version/coordinates are program checks; whether the quoted content entails the sentence is an
analyst comparison. A semantically changed judgment goes through the question writer before prose changes.

Check specifically for resolved gaps resurfacing, recovery becoming attack time, historical state becoming
current state, possession becoming execution/communication/exfiltration, and a row answering a different
question. Reuse valid review dispositions unless their proposition or supporting scope materially changed.
Finish Korean editing outside exact evidence quotes. Preserve unresolved conflicts visibly and keep draft,
semantic review, layout verification, report-artifact integrity and original evidence verification distinct.

For a local claim correction, use answer-question's ordered `retain_claim_ref` entries for unchanged
current claims and exact citation selections for replacements. Read current claim_refs; do not reconstruct
untouched citations. Preserve affected report/review staleness until the corrected basis is checked.
