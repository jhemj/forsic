# Bounded report completion from current evidence

Use the existing native tools, current question owner and report writer. This is
an analytical procedure, not a new agent loop, scheduler or permission grant.

## Resolve answerable scope before declaring a blank

For acquisition time, incident/entry time and personal-data presence/exposure/
transfer, distinguish **not yet examined**, **supported estimate**, **bounded
finding**, and **an actual constraint**. Unknown does not mean unanswerable.

1. Read the relevant retained results completely enough to establish their scope.
   Follow exact source-card read calls; do not repeat successful collection.
2. Compare a useful inference with its strongest alternative. State its subject,
   causal prerequisite or sample scope, original time precision, year and clock
   assumptions. Save changed facts/inferences in the current owning question.
3. If an authorized, feasible check could change the answer, perform that bounded
   check with existing tools before final writing. Read `/report_research` using
   its returned call for current gaps, feasibility and question-owner navigation.
   Do not edit a historical question or invent a new execution path.
4. If the material/tool/permission/budget is unavailable, the check is outside the
   requested scope, or further checks have no useful discriminating value,
   explain that actual constraint and the reopening condition. This can be a
   complete limited answer; exhaustive speculation is not required.

`needs_investigation` is for a specific available material, usable tool and
discriminating result under the current budget. Name those in checked/reason and
next_check. Importance alone or a hypothetical log that has not been supplied
does not make a check feasible. If the relevant source inventory is exhausted,
use limited with that constraint and a conditional reopening action. Do not
repeat collection merely because a final report still contains unknowns.

For acquisition: compare actual acquisition logs and image headers, chain-of-
custody/completion records and independently labelled file/conversion metadata.
A completed acquisition statement may support a qualified completion date; a
supported acquisition start/end may support an interval. Present that narrower
result even if the exact instant is unknown. Do not substitute file creation,
conversion or analysis dates for acquisition, or guess a timezone or midnight.

For personal data: inspect the selected accessible application/database/backup/
user-data locations as relevant. If candidate paths are not known, bounded inventory of the already
authorized image is the next investigation step; the user need not supply every directory. Choose targets
from actual returned inventory/configuration results, not guessed paths. A report that says 미수행 has
not answered the possession question merely by disclosing it. Distinguish an authorized useful check
not started from an actual permission, inaccessible-format/material, budget or value constraint.
`assessed_unresolved` with `feasible_next_action=none` is an analyst disposition, not independent proof
of infeasibility. Compare its reason and actual prerequisites before accepting scoped closure; correct
it through the current-owner recovery path if a useful check remains. Do not force confirmation or
scan the entire disk merely because privacy is important. Use bounded read-only inventory, format/schema
inspection and authorized sensitive-data checks; summarize types and paths
without unnecessary personal values. Separate possession from accessible
permissions, actual actor/process access and external transfer. Record the
examined population and unexamined locations. A negative sample is not universal
absence; malware or C2 indicators do not answer data-possession questions.
Never execute a recovered binary, restore a service or connect to an IOC to fill
the report. Missing passwords or inaccessible storage are constraints, not safe.

## Write from proposition-specific evidence

From compose choose `evidence_keys` plus its current `snapshot_id` to obtain a
narrow source packet. `source_cards_call` pages the full current catalog. Claims
are analyst propositions, gaps are scope records, and originals remain distinct.
For each named value, support both `text` and `detail` with only its own keys.
Read the group's instruction and node_purposes before choosing those keys; do
not fill an incident-time field with an acquisition date from a different scope.
Split unrelated propositions across rows or short lines when their support
differs. Never borrow an adjacent cell's citation or treat the aggregate answer
as proof. Compare the original's actual words and coverage; do not rewrite an
explanation as a direct quote. Repeated handles of one source are not independent.

Every displayed `time_range` includes `subject`, `qualifier` and `reasoning`:
`basis_keys`, `timestamp_role`, `premise`, `alternative`, `year_basis`,
`timezone_basis`. Use an observed account-activity window as that activity, not an
intrusion bound. A supported unauthorized action can bound access no later than
the action only when the causal, actor/host and clock assumptions hold. A normal
login, metadata change or acquisition alone cannot do so. Keep the decisive
qualification visible in the short text/details as well as the review record.

## Review once, repair material deltas, finish

Complete factual detail groups and time/scope first; synthesize event overview
and overall judgment last. Reuse unchanged accepted fields. Named-form shape
normalization does not change facts; semantic errors require explicit correction.

The whole-document review includes `answerability_checks` for each returned
node. `checked` records what was inspected, `basis_keys` selects actual current
support, and `reason` explains the result. Choose `answered`, `estimated`,
`limited` or `needs_investigation`. For the latter two give `next_check`; `limited`
also needs the real `constraint`. For report_identity this check concerns the
acquisition value, including its label and inference. An unexamined but useful
authorized check is `needs_investigation` and cannot pass readiness. Follow its
research recovery, update the current question, then only the affected prose.

Compare summary, body, timeline and appendix with the same current claims and
originals. Keep a stable finding ID and affected node/version. Material errors
include unsupported time/actor/causality, wrong quote/citation, an omitted useful
finding, a hidden consequential limit or unreadable/truncated output. Correct
them; then review that resulting version through the configured independent
path. Do not reset earlier review rounds or lose their pending dispositions.

Minor wording preferences remain `retained` and nonblocking when meaning,
scope and readability are sound. Do not regenerate accepted prose just to improve
an ending. An identical save with a new operation ID preserves its draft and
review; changed meaning/support still requires review. No fixed retry count
certifies truth. A repeated failure without new evidence must lead to diagnosis
or an honest constrained handoff, not the same authoring/review cycle.

Render the accepted version, verify exact references/quotes and bundle integrity,
then inspect actual screen and selected print scope when available. Check long
originals, folded explanations, overflow and empty pages. Keep browser/print
unavailability explicit; do not treat a successful render or hash as visual
approval. Select the verified delivery version with finalize. Its report_work
directs delivery of the existing bundle, not a new rewrite. Report remaining
limits and verification restrictions. Native goal completion additionally needs
the requested investigation's scoped closure and no running/unassessed work.
Never clear a manual stop or extend budgets/permissions to achieve completion.


## 보고서 후속 작업과 조사 질문의 구분

인증된 native 보고서 handoff에서는 이전 질문을 읽기 전용 보고 근거로 사용한다. 보고서 편집·전달을 위해 증거 없는 조사 질문을 추가하거나 report tool 결과를 원본 evidence_id로 저장하지 않는다. 새 실질 조사만 현재 소유 질문으로 등록한다.

reports.followup_task가 빈 자동 생성 추적 질문을 행정 작업으로 식별하면 해당 질문에 침해 판단·허위 인용을 만들어 scope closure를 강제하지 않는다. 현재 본문 검토·독립 검토·의견 처분·동일 버전 최종 선택을 마친 뒤 선택본 전달로 진행한다. 이 분류는 기존 원장이나 질문 상태를 수정하지 않으며 실제 조사 질문, 검토 의견, 화면·인쇄 확인 및 사용자의 전체 목표는 그대로 남는다.
