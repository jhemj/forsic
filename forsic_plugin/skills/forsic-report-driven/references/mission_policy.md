# Optional advance checks

Use a mission when preserving support, refutation, or inconclusive conditions and exact inputs before seeing
a result is worthwhile. Ordinary reads, searches, and saving current answers do not require one. Follow
forensic-investigation for check priority and closure decisions.

Save the current question, gap, exact tool inputs, and discriminating conditions in forsic_mission. Execute
returned next_call, then send mission_id, result_id, current question expected_revision, citation_refs, and
outcome/reasoning_summary/limitations/next_check/operation_id together to forsic_assess after receiving the
result. No preparation receipt is needed. Do not create retrospective missions for material already read.

Saving a plan is not execution; local supports/refutes is distinct from the overall question answer. Save
changes to the overall answer through forsic_question. Observe existing running or uncertain work rather
than duplicate it. Failure, missing returns, and unevaluated results are not no-result findings or closure.
Missions extend neither permissions nor budgets.

The same question definition, scope, exact native inputs, selected evidence versions, and discriminating
conditions define the same check even when the case revision changes. Retrieve completed/unevaluated returns
through source; query existing state for running or completion-unknown work. Failure, partial coverage, and
no match do not establish successful examination of all material. Recover through the original native retry
contract; do not automatically repeat by changing only mission ID or operation_id. When relevant new evidence,
inputs, or conditions change, design a check for that difference. Report audit has no authority to retry,
execute, or clear a manual stop.
