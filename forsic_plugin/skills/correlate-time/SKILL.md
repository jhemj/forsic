# 사건 시간축
로그 발생 시각, 수집 시각, 파일 mtime/ctime/atime을 구별한다. ctime을 생성 시각으로
단정하지 않는다. 연도·시간대 없는 기록은 확인 전까지 불명으로 남긴다.
로그 파일명·mtime은 본문에 보존된 최초/최종 사건 시각과 다르다. 목록만 보고 과거
기간의 로그가 없다고 확정하지 않는다. 필요한 범위의 본문·회전 정책을 확인하고,
확인하지 못했다면 보존 범위도 미확인으로 남긴다.
파일 stat 시각은 직접 날짜를 계산하지 않는다. timeline 항목에 time_source:
{evidence_id: stat의 전체ID, field: mtime 또는 ctime 또는 atime}와 description,
evidence_ids를 넣으면 보존된 epoch에서 코드가 변환한다. 도구의 times_kst도 확인한다.
로그 시각은 time_source에 {field: log, evidence_id: 전체ID, pointer: /lines/0/text,
literal: 원문의 시각 문자열, byte_start: 해당 text 안 UTF-8 시작 위치}를 넣고 description,
evidence_ids를 연결한다. 줄 번호가 아니라 반환 배열 위치를 pointer에 사용한다. 이 연결이 있어야
두 보고서의 시간축에도 원문과 함께 표시된다. offset을 포함한 ISO 시각은 KST로 변환하고 원시값도
보존한다. 연도·시간대가 없는 syslog 등은 원문 상태로 남긴다. 날짜나 시간대를 임의로 붙이지 않는다.
사람이 읽을 사건 문장을 쓰되 원문에 없는 성공·행위자·인과는 넣지 않는다. 같은 출처의
같은 사건은 중복하지 않고, 근접 시각만으로 인과를 확정하지 않는다.
사건 시간축에는 사건·자료의 시각을 기록한다. 포식이의 검토·해시 계산·보고서 생성 시각은
조사 작업 기록에 이미 남으므로 사건 발생 시각처럼 섞어 넣지 않는다. 웹 정렬을 맞추려고
모르는 시간대를 붙이지 않으며, 시간대 미확인 기록은 원문 날짜순의 별도 구역에 표시된다.

## 시각의 정확한 변환과 사건 의미는 별개

표시 시각이 정확해도 그것이 침입·설치·삭제·실행 시각이라는 뜻은 아니다. 먼저
파일시스템·도구가 반환한 필드의 의미를 확인한다. ctime은 상태 변경, mtime은 내용
변경, atime은 접근에 관한 메타데이터이며 구체적인 동작·주체·프로그램 실행을 단독으로
입증하지 않는다. 디렉터리 시각을 특정 하위 파일의 생성·삭제 시각으로 옮기지 않는다.

시간축의 관측 항목에는 대상과 필드명을 그대로 명시한다. 사건 행위의 시점으로
해석하려면 그 행위를 보여 주는 로그·변경 이력 등과 연결하고 경쟁 설명을 검토한다.
연결이 없으면 메타데이터 관측과 미확인 사건 시점을 분리한다. 채팅에도 같은 규칙을
적용하며 이미 잘못 붙인 행위 설명은 시각 숫자를 유지하더라도 명시적으로 정정한다.

파일 전체의 mtime/ctime은 현재의 특정 줄이 그 시점에 작성됐거나 이미 존재했다는 증명이 아니다.
줄의 도입 시점을 말하려면 이전 버전·변경 기록 등 그 줄의 이력을 보여 주는 자료가 필요하다.
접근 시각만으로 접근한 프로그램·계정·원인을 식별하지 않는다. 현재 비어 있는 디렉터리는 현재
할당 항목 목록의 관측이며, 디렉터리 자체 삭제나 특정 파일의 과거 삭제 사건으로 바꾸지 않는다.
