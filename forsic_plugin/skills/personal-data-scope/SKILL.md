# 개인정보가 어디까지 확인되는가

개인정보 질문이 있거나 발견 내용이 영향 범위를 바꿀 때 적용한다. 모든 사건에서 전 디스크
개인정보 수집을 시작하지 않는다. 기존 노트·반환 결과를 먼저 확인해 같은 수집을 반복하지 않는다.

보유 → 접근 → 반출 준비 → 전송을 다른 명제로 나눈다. 파일명만으로 보유를 확정하거나
보유만으로 유출을 확정하지 않는다. 관련 문서/내보낸 CSV/로그에서 스키마·레코드 종류·기간과
최소 표본을 확인한다. 원본 DB·압축·문서 형식 파서가 없으면 지원되는 텍스트 읽기로 대체했다고
하지 말고 필요한 형식과 다음 확인을 남긴다.

- 표본에는 필요한 최소 필드만 제시하고 개인 값은 마스킹한다. 이름이나 숫자 패턴만으로
  개인정보 유형을 확정하지 않는다. 로그의 예시/테스트 자료와 실제 레코드를 구별한다.
- 표본 수, 전체 파일 크기, 고유 사람 수는 서로 다르다. 전체 범위를 세지 않았다면 총원·총량을
  추정 집계하지 않는다. 어떤 파일·기간·구간을 읽었고 무엇을 못 읽었는지 기록한다.
- 접근은 감사/인증/애플리케이션 조회 기록과 대상·주체·시각을 대조한다. 계정 보유나 파일 atime만으로
  내용을 열람한 사람을 확정하지 않는다.
- 반출은 압축/복사 흔적과 전송 기록의 파일·시각·세션 연결을 확인한다. 정상 백업/업무 내보내기와
  구별할 원문이 필요하다. 이후 data-movement 절차로 연결할 수 있다.

현재 답을 forsic_note에 남기고 중요한 공백만 report-driven 미션으로 연결한다. 임원용에는
확인된 정보 종류·범위, 접근/전송의 현재 답과 한계를, 실무자용에는 원문 위치·검사 범위를 담는다.
신고·통지·법적 판단이나 경영 결정을 대신하는 절은 추가하지 않는다.
