현재 설계 방향: 포렌식 전문 에이전트
=================================
Hermes native 루프·goal·session·압축을 실행 기반으로 유지한다. 에이전트가 자료 탐색, 가설 비교,
복구, 우선순위와 종결을 판단한다. Forsic은 원본 보호·권한·정확 실행·보존 원문·출처 연결을 제공한다.

기본 경로는 질문 → 직접 읽기/검색 → 명시적 근거 선택과 현재 판단 → 필요한 추가 조사 → 보고다.
forsic_question은 생성·수정·근거에 연결한 판단의 단일 쓰기 경로다. 읽기에 붙은 C2 참조나 source
조회의 C1 참조를 선택하면 프로그램이 원문 버전·UTF-8 좌표를 검증한다. 기존 노트 writer의 원자적
저장으로 답·관측·채택 주장·정정 이력을 보존한다. 미션/Test/Assessment를 자동 생성하지 않는다.

미션은 사전 조건이 필요한 판별 검사에만 쓴다. 선택했다면 기존 실제 실행 결속과 국소 평가를 유지한다.
평가는 명시적으로 선택한 미션·결과·인용과 현재 질문 revision으로 한 번에 처리하며 준비 도구가 없다.
전용 질문 생성, 사후 미션 등록, 평가 준비, 구형 보고서 작성 도구는 현재 native 목록에서 제거했다.
이전 원장·보고서·평가 영수증의 해석 및 내부 호환 API는 보존한다. 노트 도구는 이력 조회만 노출한다.

구조 검사와 정확 인용은 의미 정확성을 승인하지 않는다. 미검토 범위·반론·불확실성을 드러내고
요청에 답했는지로 종결한다. 고정 점수·모든 파일 검사·미션 완료 수를 조사 성공으로 삼지 않는다.
모델/권한 확대, 새 사건, 별도 실행기·판단 DB·LLM 압축기·자동 리뷰 루프는 이 변경에 포함하지 않는다.

아래는 보존된 구성 설명이며 위 책임과 충돌하는 절차 중심 해석은 적용하지 않는다.

FORSIC 화면 설계 원칙 (2026-10-06)

정보 구조·시각 체계·사용 흐름의 세 독립 검토를 합쳐 다음 원칙을 적용했다.

1. 증거 경로가 사건의 조사 범위를 정의한다. PTY 실행 폴더(cwd)와 혼용하지 않는다.
   선택된 원본 경로(scope)를 사건보다 위에 읽기 전용으로 보여준다.
   원본 변경은 기존 사건의 경로 편집이 아니라 새 사건 접수다.
2. 사건 안에 대화와 조사 결과가 속한다. 전역 최근 세션을 사건 아래 표시하지 않는다.
   압축으로 이어진 native 세션은 한 대화로 묶고 실제 사건 소속으로 검증한다.
   사건 ID와 대화 ID가 맞지 않는 주소는 native 대화를 시작하지 않는다.
3. 새 사건은 경로 접수 후 빈 첫 대화를 만든다. 새 대화는 선택된 사건에 연결한다.
   새 대화에는 이전 메시지·모델 결론·목표를 자동 복사하지 않는다.
   생성 요청은 UUID로 중복을 방지하며, 재시도 때 같은 요청 ID를 유지한다.
4. 왼쪽 탐색 순서: 사건 목록/새 사건 → 증거 경로 → 현재 사건 → 대화 → 조사 보드/보고서.
   포식이 캐릭터·상태는 왼쪽 상단에 항상 고정한다. 캐릭터 영역은 데스크톱104px/모바일80px이며 활동 문구를 옆에 유지한다. 저장한 사례·모델 연결·설정은 하단에 배치한다.
   전체 대화, 실행 폴더, 내부 압축 세션 등 구현 개념을 주 탐색에서 제외한다.
5. 공통 디자인 토큰은 web/src/forsic-shell.css가 소유한다.
   차콜·중성 회색을 기본으로 쓴다. 새 대화는 밝은 무채색 버튼, 선택 항목은 배경과 전체 테두리로 구분하며 왼쪽 색상 강조선을 쓰지 않는다.
   기본 메뉴 폭 288px, 모바일 메뉴는 최대320px. 간격4/8/12/16/24/32px.
   컨트롤·카드·대화상자는 모두 반경0의 직사각형이다. 캐릭터의 광학적 원형은 일러스트로 유지한다. 보조문구도 읽을 수 있는 대비를 유지한다.
   모바일 메뉴의 배경 입력을 차단하고 Escape/Tab/포커스 복귀를 지원한다.
6. native Hermes TUI가 실제 채팅·도구·입력을 담당한다. React에서 별도 채팅을 만들지 않는다.
   도구 호출은 차분한 회색, 답변은 기본 본문색, 오류는 기존 오류색으로 구분한다.
7. 보고서는 다운로드를 먼저, 판단·남은 확인은 펼쳐 볼 수 있게 배치한다.
   파일 생성, 연결됨, 목표 active를 조사 완료나 증거 검증 성공과 혼동하지 않는다.
8. Telegram assistant 메시지는 Markdown을 평문으로 변환한다.
   코드·경로·URL·근거 ID와 사용자 원문은 보존하며 민감정보 마스킹 후 길이를 분할한다.
   첨부 보고서 파일의 본문 형식은 바꾸지 않는다.

9. 사건 목록의 항목 본문을 클릭하면 해당 사건의 마지막 대화로 이동한다.
   별도 대화/보드 버튼은 두지 않고 보관 아이콘만 둔다. 보관함에서는 복원 아이콘을 쓴다.

10. 대화 제목은 내용 요약으로 생성하지 않는다. 사건 안의 생성 순서로 첫 번째 분석, 두 번째 분석처럼 표시하고 최근 활동 정렬과 무관하게 번호를 유지한다.
