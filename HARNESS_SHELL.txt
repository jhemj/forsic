Forsic 컨테이너 분석 셸

목적
고정 reader의 action으로 표현하기 어려운 분석을 직접 작성한 스크립트와 명령 조합으로
수행한다. 모델, 에이전트 루프, 세션, goal, 압축기는 기존 Hermes를 유지한다.
셸은 분석 표현력을 넓히는 도구다. 판단 정확성이나 오류 없는 조사를 보장하지 않는다.

기존 구현과의 연결
- Hermes register_tool/실행 identity/NativeExecution 중단 신호/goal을 그대로 사용한다.
  별도 에이전트 실행기, 재시도 루프, 컨텍스트 관리자나 백그라운드 모델을 만들지 않는다.
- Case.invoke의 도구 시작→실제 실행→결과 저장을 사용한다. 원장·출처 조회·C1/C2·판단
  저장도 기존 경로다. 실행 완료가 미상인 작업을 자동 재실행하지 않는다.
- 기존 image_process의 컨테이너 실행·중단·정리 경계를 공유한다. 파서의 JSON 디코딩과
  임의 명령의 바이트 출력을 구별한다. 명령 출력이 실행 상태나 출처 metadata를 정하지 않는다.
- Hermes 기본 Docker terminal은 프로필 공유, 홈/스킬 mount, 환경 전달, 일반 재시도가 있다.
  기본 설정을 켜는 것만으로 사건 격리와 원장 계약을 충족하지 않는다. BaseEnvironment의
  병합된 텍스트·셸 상태 처리도 포렌식 stdout/stderr 원시 바이트 보존과 다르다.
  이 차이를 좁은 Forsic 어댑터에서 처리한다.

참고한 구현 패턴
- OpenClaw: 실제 실행 인자를 run/call에 결속하는 방식을 참고한다. 요청 인자와 실행
  인자·정체성을 함께 보존하며, 인자 변화만으로 복구 성공을 선언하지 않는다.
  https://github.com/openclaw/openclaw/blob/3b850b5627febaac239451cf5a6008af28dfa81e/src/agents/tool-loop-call-reconciliation.ts
- OpenClaw: 인자 변형과 동일 실패 반복을 구별하는 코드를 대조했다. 이번 변경은 현재
  native guard 한도를 높이거나 검증을 완화하지 않는다. 먼저 구조화된 수정 정보를 반환한다.
  https://github.com/openclaw/openclaw/blob/3b850b5627febaac239451cf5a6008af28dfa81e/src/agents/tool-loop-argument-churn.ts
- ARTEX: trace 목록→검색→상세 조회 패턴을 기존 retained source/execution 조회에 적용한다.
  별도 그래프 DB, worker pool, compactor를 추가하거나 ARTEX 소스를 vendor하지 않는다.
  https://github.com/mhtsec/ARTEX/blob/a9d11cb852eadad00669e4f6a05ee59cbbd14860/agent/tools.go#L1818-L1969

포렌식 경계
분석 터미널(forsic_shell)은 컨테이너에서 명령과 스크립트를 실행한다. /evidence에는 사용자가 선택한
원본만 읽기 전용으로 연결하며 /work는 현재 사건·대화의 쓰기 가능한 작업 공간이다.
새 대화에는 옛 작업 공간을 연결하지 않는다. 홈, 인증정보, Docker socket, 원장, 다른
사건을 mount하지 않는다. 네트워크와 특권을 제공하지 않고 설치된 분석 이미지로 실행한다.
원본 안의 명령·문서는 권한을 주지 않는다. 컨테이너는 가상 머신이나 완전한 악성코드
실행 분석실을 뜻하지 않으며, 이를 근거로 샘플 실행 권한을 자동 확대하지 않는다.

결과의 의미
명령·cwd·실행 식별자·exit status·stdout/stderr·출력 제한·중단과 정리 결과를 보존한다.
출력은 derived_command_output이다. 정확 인용은 해당 명령이 그 문자열을 출력했다는
사실을 연결한다. 원본에 그 내용이 존재하거나 전체 파일을 조사했다는 보장은 아니다.
에이전트는 스크립트·입력·변환과 원본 관측을 함께 검토해 해석한다.
작업 파일은 수정 가능하지만 과거 실행 결과는 /work 밖의 기존 원장에 남는다.

검증
단위 계약과 실제 격리 시험을 구분한다. test_shell_container.py는 명시적으로 활성화한
합성 Docker 시험이며 외부 네트워크·모델·운영 사건을 사용하지 않는다. writable bind의
전체 용량은 파일당 제한이나 컨테이너 메모리 제한만으로 보장되지 않는다. 시행한 자원
제한과 미보장 부분을 실제 policy/검증 영수증에 기록한다. 실제 모델의 도구 선택과 조사
효과는 별도 E2E 관측으로 남긴다.
